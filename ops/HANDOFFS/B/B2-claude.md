## 风险与需要审查的点

- `/fs/directories` 能枚举主机上的目录名。接口要求 token，开发态服务只监听
  `127.0.0.1`；若把后端暴露到局域网且 token 外泄，持有者可以枚举目录结构。
  这是「浏览器里必须能选任意本机目录」的直接代价，需要确认部署边界。
- 目录浏览器以项目当前目录的真实路径为起点；取真实路径失败时退回盘符列表，
  功能仍可用，但需要多走几层。
- **旧对话没有按会话记录 workspace**：打开已有对话时只能跟随项目当前活动目录。
  如果用户中途换过目录，旧对话显示的目录可能不是它当初实际用的那个。要精确
  还原需要给 thread/task 加 workspace 记录（数据库变更），本轮未做。
- 绑定目录后不会自动解绑旧目录，项目下会保留多个绑定；这是现有设计
  （切目录 ≠ 删绑定），需要审查是否符合预期。
- **纯聊天只做了“不碰电脑”的边界**：没有目录时问「你好」可以答；要求改文件
  会被引导选目录，这是预期。选目录后恢复完整 Agent，此时否定式指令仍可能被
  动作词判成“要干活”（真机：说“只回复 OK，不要读取文件”仍去翻代码）。
  这属于意图判定/场景策略层的问题，留到 B4，不在本轮扩大。
- 首屏不再展示场景/授权/起手式；默认授权档仍是「询问」，不会静默放宽。

## 建议人工验收

1. 打开 `http://127.0.0.1:3000/`，按「新对话」：标题应为「我们要做什么？」，
   目录下拉显示「选择目录」，不得自动出现项目上次的目录。
2. **不选目录直接发送「你好」**：应正常回答，底部显示「当前是纯聊天」，
   不报错、不弹目录框；侧栏出现这条会话。
3. 不选目录发送「帮我把 README 改一下」：应提示先选择工作目录，并让点
   「选择目录」，不得声称已经读过/改过文件。
4. 从目录下拉选一个已有目录：标题变为「我们要在 <目录> 做什么？」（无「」），
   纯聊天提示消失，恢复代码 Agent 模式。
5. 点「选择目录…」：确认目录浏览器逐级进入 / 上一级可用；选完自动绑定并切换。
6. 打开一条旧对话：目录应显示项目当前目录；再按「新对话」恢复「选择目录」。
7. 到「项目」页点「选择目录…」：确认同一目录浏览器可用；绑定后自动切到新目录。
