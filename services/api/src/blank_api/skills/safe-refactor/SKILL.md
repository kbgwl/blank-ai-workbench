# 安全重构

## 前提

**行为不变**是唯一验收标准。所以第一步不是改代码，是**证明现在是什么行为**。

1. 找出覆盖这段逻辑的测试；没有就先补几条（记录当前输出当作期望值）。
2. 记录基线：跑一遍，记下退出码与用例数。

## 小步法

每一步只做一种变换，做完立刻跑测试：

| 步骤 | 例子 | 不许同时做 |
|---|---|---|
| 改名 | 变量/函数改名 | 不动逻辑 |
| 提取 | 抽函数、抽常量 | 不改签名调用方 |
| 内联 | 去掉中间层 | 不改行为 |
| 移动 | 换文件/换模块 | 不改内容 |
| 替换实现 | 新写法替旧写法 | 不改对外契约 |

一次提交只做一格。跨格混在一起，出问题时无法判断是哪一步坏的。

## 收尾

- 对外契约（API 字段、函数签名、CLI 参数、文件格式）如果变了，这**不是重构**，是改行为——要单独说，并同步调用方与文档。
- 报告里写清：改了几步、每步验证结果、哪些行为**确认没变**（靠哪条测试证明）。

## 禁止

- 不做「顺手优化」：格式化、改名、重构混在一个改动里，审查成本翻倍。
- 不在没有测试的模块上做结构性重构；先补测试，或者如实说明风险。
