# 逆向取证

## 先判形态，再选工具

| 形态 | 特征 | 入手 |
|---|---|---|
| Electron | 有 `resources/app.asar` | 拆 asar 头（4 字节 pickle + 4 字节 header size + JSON） |
| 编译后单文件 | 几百 MB 的 `.exe`，无 js | `grep -a` 找字符串常量、提示词、错误文案 |
| 托管/打包 | 有 `.dll` / `.pyz` / `.jar` | 先找清单文件与类型定义，再看逻辑 |
| 提取过类型 | 带 `*.d.ts` / `*.pyi` | **优先读它**：字段、必填、上限注释都在，比混淆代码可靠 |

## 关键手法

1. **asar 解析**：`unpacked: true` 的文件没有 offset，要跳过——否则整个 header 解析全错。
2. **字符串定位**：`LC_ALL=C grep -aoc "<pattern>" file` 先确认有没有，再用
   `grep -ao ".\{0,120\}<pattern>.\{0,200\}"` 取上下文。二进制里字符串常被 `\0` 打断，
   取出来先 `tr -d '\000'` 再读。
3. **系统提示词**：搜特征句（如 `You are ...`、`<instructions>`），往前扩 300、往后扩 4000。
4. **资源文件**：CSS/JSON 直接从包里按 offset 读出来落盘，再统计（字号、颜色、间距）。

## 结论要求

- 每条结论都要能指回**证据位置**：文件路径 + 偏移/行号 + 原文片段。
- 区分「看到的」与「推断的」：看到的写原文，推断的标"推断"。
- 拿不到证据就说拿不到，不要用"大概是这样"填坑。

## 落盘

把提取出的原文存到临时目录（如 `E:/tmp/<product>/`），分析结论写成报告：
**能力清单 / 机制差异 / 值得移植的部分 / 证据附录**。
