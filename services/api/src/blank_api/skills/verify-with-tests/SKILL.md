# 用测试收尾

## 顺序

1. **先写一条会失败的用例**（或先跑现有用例确认它是绿的）。
   - 修 bug：用例复现 bug，改之前必须是红的。
   - 加功能：用例写清输入与期望输出。
2. **改到它变绿**，同时跑相邻用例，确认没有连带失败。
3. **跑一遍相关范围的回归**（不必全量，但要说清跑了哪些、没跑哪些）。

## 记录口径

每条验证都记三个东西：**命令 / 退出码 / 数量**（通过几项、失败几项）。
示例：`pytest -q tests/test_x.py → EXIT=0，12 passed`。

没有跑就说「未验证」。**不允许**用「应该没问题」「逻辑上是对的」代替验证结果。

## 前端/页面类改动的额外一步

- 类型检查（`tsc --noEmit`）与单测都要跑；只跑一个不算过。
- 有界面改动就实际打开看一眼，别只看编译通过。

## 收尾报告

```
验证：
- <命令> → EXIT=<code>，<通过数>/<总数>
- <未覆盖到的部分>：未验证（原因）
```
