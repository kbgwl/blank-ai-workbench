# 摸清一个仓库

## 读的顺序（不要一上来就读代码）

1. **入口文档**：`README`、`AGENTS.md`、`CLAUDE.md`、`CONTRIBUTING`、`docs/` 里最上层那几篇。
2. **构建与运行**：`package.json` / `pyproject.toml` / `Makefile` / `docker-compose`。
   找到四条命令：装依赖、跑起来、跑测试、做类型检查。
3. **目录地图**：`list_files` 两三层，写下"哪个目录放什么"。这一步是为了后面能猜对位置。
4. **现有约定**：命名、错误处理、日志、测试组织方式。**跟现有风格走**，不要带自己的偏好进来。

## 输出（写进对话，不写进仓库）

```markdown
## 这是什么
（一句话：解决什么问题，给谁用）

## 怎么跑
- 安装：<命令>
- 起服务：<命令>
- 测试：<命令>（当前 <N> 项）
- 类型检查：<命令>

## 目录地图
- `src/...` → ...
- `tests/...` → ...

## 几条不成文的约定
- （从代码里看到的真实惯例，比如"所有外部调用都包了 retry"）

## 风险点
- （没有测试覆盖的核心模块、锁死的老依赖、奇怪的构建脚本）
```

## 注意

- 只读不写：调研阶段不改任何文件。
- 别把「我要开始工作了」这类过程话写进输出；直接给结论。
- 没找到测试命令就如实写「未找到」，不要编一个。
