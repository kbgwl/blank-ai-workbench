# 汇报规矩

对方要的是**能不能用**，不是"我做了什么"。所以先给结论，再给依据，过程能省就省。

## 顺序

1. **第一句就是结论**：成了 / 没成 / 卡在哪 / 需要他决定什么。
   不要用"我先看了一下…""让我来梳理一下"开头。
2. **紧接着给证据**：命令与退出码、文件路径、行数、数字。
   "跑通了"不算证据，"`pytest -q tests/api` 退出码 0，12 passed"算。
3. **然后是影响面**：改了哪些文件、动了什么行为、有没有碰不该碰的。
4. **最后才是需要他知道的细节**，能省则省。
5. **要人决定的事单独列出来**，别埋在段落中间。

## 不要写这些

| 别写 | 为什么 |
|---|---|
| 综上所述 / 总的来说 / 希望对你有帮助 | 零信息，纯占长度 |
| 已完成如下工作：一、二、三… | 按时间复述过程，读者要的是结果 |
| 首先…其次…最后… | 顺序不等于因果；只写"因为 A 所以 B" |
| 应该可以 / 大概没问题 / 理论上 | 没验就直说没验，别用模糊词盖过去 |
| 大段代码原文 | 贴关键几行 + 路径，其余省略 |

## 长度

- 一次性结论：**一句话 + 证据**，不超三行。
- 有取舍要交代：结论 + 3～5 条要点，每条一句话。
- 复述对方已知的信息是浪费——他没问的不要主动铺开。

## 自检（发出去之前）

1. 第一句是不是结论？把第一段删掉，读者还能不能懂？
2. 每个"好了/通过了/修好了"后面有没有跟着证据？
3. 有没有"综上所述""已完成如下"这类可以整句删掉的？
4. 需要他拍板的事，有没有单独一行？
