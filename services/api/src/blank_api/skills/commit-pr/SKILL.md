# 提交信息与 PR 描述

## 先读 diff

`git diff`（暂存区用 `git diff --cached`）。**必须基于真实改动写**，不能凭记忆。

同时看：本次有没有新增依赖、有没有改数据库结构、有没有删掉公开接口——这三样必须在描述里点名。

## 提交信息

```
<动词> <对象>：<一句话说清做了什么>

<为什么这么做；不写"修改了一些问题"这种空话>
```

- 第一行 ≤ 50 字符，不加句号。
- 一个提交只做一件事。两件事混在一起就拆。
- 不在描述里写"本次由 AI 生成"之类的自指废话。

## PR 描述

```markdown
## 改了什么
- （按影响面列，不按文件列）

## 为什么
（问题是什么、为什么现在改）

## 怎么验证的
- <命令> → EXIT=0，N passed
- 没覆盖到的：<如实写>

## 风险与回滚
（影响哪些老数据/老客户端；怎么退回）
```

## 禁止

- 不把文件列表当改动说明（`修改了 a.py、b.py、c.py` 没有信息量）。
- 不在验证没跑的情况下写「已测试通过」。
- 不用 `git commit --amend` 改已推送的提交，除非用户明确要求。
