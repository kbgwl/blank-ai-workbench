# 定位根因

## 铁律

**没复现就不改。** 改不动根因的修补只是把问题推迟一次。

## 步骤

1. **复现**：把失败命令原样跑一遍，记下完整输出与退出码。
   - 报错信息里出现路径/行号，先去那一行看，不要从调用栈顶部往下猜。
2. **缩小范围**（二分）：
   - 二分输入：把触发数据减半，直到最小可复现样本。
   - 二分版本：`git log`/`git diff` 找最近一次相关改动；能 `git bisect` 就 bisect。
   - 二分链路：在上下游加一行打印/日志，确认值是在哪一段变坏的。
3. **验证假设**：每次只改一个变量，跑一次，看结果是否按预期变化。
   一次改三处再跑，「好了」也说不清是哪一处起效的。
4. **修根因**：改造成问题的那一层，不要在下游加 `if` 绕过去。
5. **加护栏**：补一条能复现原问题的测试，防止再犯。修完这条测试必须由红转绿。

## 常见误判

- 把「超时」当成根因：超时是症状，要查它为什么慢或为什么卡住。
- 把「偶发」当成不可查：偶发通常是并发、时序或缓存，找共享状态。
- 把「加个 try/except 不报错了」当成修好：那是把证据藏起来。

## 输出

一句话说清：**现象 → 根因（哪一层、哪一行）→ 改法 → 验证结果**。
