# 安全审查

## 输入面先画清

列出所有**外部可控输入**：HTTP 参数/头/Cookie、上传文件名、URL 参数、Webhook、第三方回调、
环境变量、被读取的文件内容。每个输入都追到它最终落地的地方。

## 六类必查

1. **注入**：字符串拼 SQL / shell / 模板 / 正则；`eval`、`exec`、`system`、`popen`；
   路径拼接后没做 `..` 与绝对路径校验（`Path.resolve()` 之后必须仍在根目录内）。
2. **鉴权与越权**：接口有没有校验身份；校验的是「登录了」还是「有这条数据的权限」；
   批量接口能不能靠改 id 读到别人的数据（IDOR）。
3. **密钥与凭证**：密钥是否硬编码、是否进日志、是否回显给前端；错误信息里是否带内部路径。
4. **上传**：类型靠后缀还是内容；落盘目录是否可执行；大小与数量上限；同名覆盖。
5. **依赖**：新增依赖是否必要、是否活跃维护；锁文件有没有一起提交。
6. **日志与错误**：堆栈是否直接返回给调用方；敏感字段是否脱敏。

## 输出

按 `高危 / 中危 / 低危` 三档，每条给：
- 触发条件（攻击者要能做到什么）
- 影响（能读到什么、改到什么）
- 修法（具体到改哪一行、加什么校验）

只报**能构造出攻击路径**的问题。构造不出来就写「未发现可利用路径」，不要罗列泛泛的最佳实践。
