# 文档同步

## 先找"会说谎的地方"

改完代码，用 `search_code` 搜**旧的字面量**（旧字段名、旧默认值、旧命令），
命中处就是必须同步的地方：README、API 文档、示例代码、注释、前端文案、`CHANGELOG`。

## 同步范围判定

| 改了什么 | 必须更新 |
|---|---|
| 新增/删除接口字段 | API 文档 + 前端类型 + 示例 |
| 改默认值 | 文档里的默认值说明 + 迁移说明 |
| 改行为（同样的输入不同输出） | 文档 + `CHANGELOG` + 受影响用例 |
| 纯内部重构 | 只需要改注释里过期的描述 |

## 写法

- 文档与代码用同一套词：代码里叫 `workspace`，文档不要写成"项目空间"。
- 示例必须能跑：贴命令就贴能直接复制的完整命令。
- 变更记录写"对使用者的影响"，不写"重构了 XxxService"。

## 收尾

报告里列出：改了哪几处文档、每处对应哪一处代码改动。**没同步的要明说**（比如"文档站不在此仓库，未改"）。
