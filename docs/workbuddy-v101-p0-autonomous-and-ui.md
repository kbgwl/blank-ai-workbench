## 2. P0：后端真正接管自动执行

### 2.1 当前问题

当前链路类似：

```text
POST /threads/{thread_id}/turns
→ 后端创建任务
→ 前端读取 auto_start
→ 前端调用 runTask
```

这不是真正的自主执行。窗口关闭、前端崩溃或网络断开后，任务可能停在 planned/queued。

### 2.2 修改要求

在后端统一实现：

```text
用户消息
→ Chat Supervisor
→ 创建 Goal
→ 创建 Task
→ 生成权限/场景/模型快照
→ 写入 dispatch snapshot
→ auto_start=true 时后端立即入队或启动 Runner
```

不能依赖浏览器或 Electron 前端调用 `runTask` 才开始执行。

必须保证：

- 同一个任务不能重复创建 run；
- queued/running 任务不能重复派发；
- 后端重启后 queued 任务可以被 worker 接管；
- 前端只展示状态，不决定任务是否启动；
- 派发失败记录 `task.dispatch_failed`；
- 暂停、取消或等待审批时，后台不能偷偷继续执行。

必须记录：

```text
message.observed
goal.created / goal.linked
task.dispatched
run.created
run.started
tool.started
tool.completed
verification.started
verification.completed
task.completed
```

## 3. P0：审批对象和授权状态统一

### 3.1 当前问题

当前用户点击允许后，仍可能收到“没有同意 Clipboard_Screenshot.png”。重点排查：

- 前端展示的工具调用与后端审批对象不一致；
- 前端没有把具体审批身份传给后端；
- 后端按任务内全部 pending 工具处理；
- 审批后没有重新读取真实任务状态；
- 重试或重新生成工具调用后仍使用旧审批；
- 审批过期后界面仍显示可点击。

### 3.2 统一审批对象

审批对象至少包含：

```json
{
  "approval_id": "approval_xxx",
  "task_id": "task_xxx",
  "run_id": "run_xxx",
  "tool_call_id": "call_xxx",
  "tool_name": "clipboard.read",
  "resource_type": "file",
  "resource_path": "Clipboard_Screenshot.png",
  "arguments_hash": "sha256...",
  "risk_level": "low",
  "scope": "once",
  "status": "pending",
  "created_at": "...",
  "expires_at": "..."
}
```

审批唯一匹配条件：

```text
approval_id + tool_call_id + tool_name + arguments_hash
```

不能只根据文件名、工具名或 task_id 判断授权。

### 3.3 审批 API

请求必须支持：

```json
{
  "approval_id": "approval_xxx",
  "tool_call_id": "call_xxx",
  "arguments_hash": "sha256...",
  "approve": true,
  "scope": "once"
}
```

后端必须校验审批是否存在、属于当前 task/run、tool_call_id 和 arguments_hash 是否匹配、是否过期、是否仍为 pending。

不匹配时返回具体错误：

```text
审批对象已变化，请重新生成审批请求
```

不能只返回“没有同意”。

### 3.4 事件和幂等

```text
approval.required
approval.decided
approval.granted / approval.denied
tool.started
tool.completed
```

所有事件必须带 `approval_id`、`tool_call_id`、`tool_name`、`arguments_hash`、`resource_path`。

重复点击允许不能重复执行命令或重复修改文件。多个 pending 审批不能串台。

## 4. P0：发送栏增加权限模式

### 4.1 目标布局

```text
[场景] [模型] [权限] [记忆] [附件] [发送]
```

开发场景：

```text
[开发] [Claude] [完全访问] [发送]
```

日常场景：

```text
[日常] [Claude] [询问] [记住习惯] [发送]
```

### 4.2 三种权限

界面显示中文，内部可以映射为已有枚举：

#### 询问模式

自动允许读取、分析和低风险检查；修改文件、安装依赖、高风险命令、删除文件和工作区外路径前询问。

#### 完全访问

当前工作区内自动允许读取、修改、创建文件、运行测试、安装依赖、自动修复和连续执行多步任务；删除大量文件、工作区外路径、生产环境、发布、敏感网络操作和不可逆操作仍需确认。

#### 计划模式

只允许读取、分析、生成计划和输出建议，禁止修改文件、执行命令、安装依赖和自动提交。

### 4.3 权限快照

必须区分：

```text
设置页默认权限
当前发送栏选择
任务权限快照
工具实际执行权限
```

正确链路：

```text
settings.permissions.default_mode
→ composer.permission_mode
→ POST /threads/{id}/turns
→ task.permission_snapshot
→ run.permission_snapshot
→ tool gateway
```

任务创建后权限快照固定，不受之后全局设置变化影响。

场景和权限必须取交集：

```text
effective_policy = scene_policy ∩ permission_mode_policy ∩ safety_policy
```

```text
web/src/components/ui/SelectPopover.tsx
web/src/components/ui/DropdownMenu.tsx
web/src/components/ui/OptionList.tsx
```

所有业务下拉必须使用统一组件，不允许每个页面复制一份实现。

组件必须支持：

- 当前值、图标、标题、描述和选中状态；
- disabled、warning、loading；
- 键盘上下选择、Enter 确认、Escape 关闭；

推荐接口：

```tsx
<SelectPopover
```

### 5.3 视觉要求

- 深色主题下使用深色浮层；
- 与输入栏使用同一套圆角、边框和间距；

- 菜单宽度能显示完整名称；
- 不遮挡输入文字和发送按钮；
- 弹出方向根据空间自动调整。

场景选项必须显示说明，例如：

```text

读写代码、运行测试

创建和修改文档

日常
聊天、记忆习惯
```

权限选项必须显示权限范围，例如：


## 6. P1：真正的自主决策循环

用户说“把登录页面改成 Codex 风格，并运行测试”后，Agent 必须自动检查项目、找到页面、修改文件、运行测试、自动修复失败并再次验证。

只有以下情况才询问用户：

- 缺少必要业务信息；
- 需要工作区外权限；
- 需要不可逆操作；
- 需要发布或外部请求；
- 业务目标存在重大歧义。

不能因为 Agent 不想判断就反复询问“要不要继续、要不要运行测试、是否修改文件、下一步做什么”。

Chat Supervisor 必须监听用户消息、工具结果、测试失败、审批结果、文件变化、任务超时、后台触发器和验证结果。

控制词必须作用于已有任务：

```text
继续 / 暂停 / 恢复 / 重试 / 同意 / 拒绝 / 取消
```

测试失败后应自动判断是否可以修复。编译、类型、格式、明确路径和页面问题默认自动修复；业务歧义、数据丢失、发布、外部请求必须询问。

## 7. P1：场景策略必须真实生效

### 开发

允许读写代码、创建文件、运行测试、安装依赖和自动修复。

### 文档

允许 Markdown、Word、PDF 等文档操作，默认禁止修改源代码、执行 shell 和修改测试。

### 日常

允许聊天、分享信息、记住习惯和生成 Skill。只有日常显示：

```text
[记住习惯] / [不记住]
```

默认禁止执行命令和修改项目文件。

### 头脑风暴

允许发散、对比、质疑和形成方案，默认不自动修改文件。

### 逆向实验室

只允许在独立分析目录读取、分析和实验，禁止修改原始项目。

## 10. 真实 GUI 验收

### 下拉框

逐个打开场景、模型、权限、工作区、设置页权限、设置页自动化模式、逆向实验室筛选器并截图。不能出现浏览器默认白色菜单。

### 完全访问

1. 打开开发场景；
2. 在输入栏选择完全访问；
3. 输入“创建 test.txt 并写入 hello”；
4. 只点击发送；
5. 文件真实创建；

### 关闭窗口

1. 创建多步骤任务；
2. 任务开始后关闭窗口；
3. 等待任务执行；
4. 重新打开应用；

6. 不能停在 planned 且无人接管。

### 截图授权

1. 上传 `Clipboard_Screenshot.png`；
2. Agent 请求读取；
3. 点击允许；
4. 工具真实执行；
5. 不得再次提示没有同意；
6. 事件带完整 approval_id、tool_call_id、arguments_hash。
