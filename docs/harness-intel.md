## 一、Harness 工程的四个方向与成熟度阶梯（11-17）

**情报**：ONES 的《2026 Agent 执行框架工程》提出四个独立方向——上下文设计（把上下文
窗口当会失效的资源、`AGENTS.md` 做目录不做百科）、工具选择（最小权限、按规划/执行/
验证阶段限定工具、明确重试与转人工）、限制管理（迭代上限、时间预算、成本上限、循环检测、
自我验证关卡）、生产加固（临时沙箱、结构化日志、变更前回归）。
成熟度阶梯 L0 裸模型 → L1 可重放日志 → L2 确定性检查 + 故障归因 → L3 结构化验证报告 +
签名执行记录（可审计）。

**我们**：逐项对照下来比预想的好，但缺口具体：

| 方向 | 我们的状态 |
|---|---|
| 上下文设计 | ✅ 有账单（`context.breakdown`）、空闲压缩、结果落盘、工具说明预算 |
| 工具选择 | ✅ 按需加载（cron/团队两族收起）、按权限档限定；❌ 没有"按阶段限定工具"（规划期还在给写工具） |
| 限制管理 | ✅ 步数上限、**token 闸（含子代理合计，耗尽后只准总结）**、循环检测（stall + 进展哨兵）、验证关卡；❌ 缺**金额口径**（$） |
| 生产加固 | ✅ 沙箱档位、事件账、快照回滚；❌ 没有"变更前回归评估" |

**动作（已修正）**：我原以为"没有成本上限"，核对源码后是错的——`graph.py:5549-5645` 有
`token_budget`，且把子代理的花费合并进来算，耗尽后进入"只准总结"的收尾区。
真正缺的是**金额口径（$）**：两家外网 harness（opencode / DeepSeek Harness）也都没有金额闸，
DSH 的 Known Limitations 直接写 "No built-in turn budget"，所以这块只能自建。
细节见 `docs/external-reference-2026-11.md` §1。**（待做，降级为"补一层成本口径"）**

历史上**只加过、没删过**。已做的是"分段计量"（`compose_system_prompt_parts_sizes`），
还没真的删。

**动作**：先删 `coding` 段里"记得跑测试""注意边界"这类模型已经会做的事，用同一批任务
对比步数与成功率。**（待做，需要一轮对照实验）**

## 三、超时 shell 转后台（11-19，OpenCode 2.3.x）✅

**情报**：OpenCode 2.3.1/2.3.2 —— 超时 shell 转后台、后台 compaction。

**我们**：原来到点就杀，模型只能二选一：再撞一次 120 秒，或者不验证了（真机里选了后者）。
现在超时分支把同一条命令挪到 `shell_tasks` 后台重跑，回执给 `shell_id` 与取法。
**已落地（`558f761`）**。

## 四、"空白/缺省 = 不校验"是系统性 bug 类（11-19）

**情报**：周报点出 94.7% 的类应用未登录可访问，三段机制全部"默认放行"；
OpenClaw 一周的六类修复指向同一个 bug 类——**空白/缺省值被解释成"不校验"**。

**我们**：今天在改只读命令前缀时正好踩到同类问题的另一面（`echo hi > out.txt` 的规则会
顺带免问 `echo hi > secrets.txt`），两侧都堵了。**已落地（`da44f62`）**。

**动作**：把这条列成代码审查红线：任何 `x or ""` / `dict.get(k, True)` 形状的默认值，
先问"缺省时是放行还是拦住"。

## 六、把"假成功"改成可核验（11-16，OpenClaw）✅

**情报**：OpenClaw v2026.11.1 的重点是"可信与可观测"，把模型的"假成功"改成可核验。

**我们**：`verify_facts` 已经只读事实（零改动伪成功、假称测试通过都会被拦），

刚又用纯只读任务复核过 `changed_files`：只读任务报 0 / 空，没有假账。

## 七、钩子失败要能声明 fail-closed（11-08 / 11-16 / 11-17，Claude Code 2.1.317）⏸

**情报**：Claude Code 引入 `onFailure: "block"`——钩子失败即阻断动作，fail-closed。

**我们**：`services/hooks.py` 明确写着"钩子失败一律 fail-open（坏钩子不能把任务搞挂）"。
这对**通知类**钩子是对的，对**安全类**钩子正好相反：一个"写敏感文件前检查"的钩子崩了，
现在是直接放行。

**动作**：给 `HookSpec` 加 `on_failure`（默认 `continue`，可写 `block`），只在阻断型事件
上生效。**（待做——改动横跨启动/超时/解析三处失败分支，需要单独的判据）**
