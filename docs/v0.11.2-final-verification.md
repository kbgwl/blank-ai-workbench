## 2. §3 P0 后端自动执行

### 2.1 §3.2 十二项排查落点

`create_turn → 后端派发 → auto_start → run.created → run.started → worker/进程内 runner 消费 → provider mock → task.completed` 由 `test_backend_autostart_v101.py` 的 10 例端到端钉住；`_dump_state` 在超时时一次给出 DB 状态、是否有人认领、后台巡检任务、DB 连接、pending asyncio task、最后代码节点。数据库锁与「异常被后台吞掉」没有单独的故障注入用例，列为已知限制。

### 2.2 §3.3 30 秒超时与 13 项诊断字段

- 当前实现是 **`_wait_terminal(seconds=15.0)` 硬超时 + `pytest.fail(await _dump_state(...))`**，比任务单要求的 30 秒更严（更早失败、更早打印诊断），没有为了凑字面数字把等待放宽到 30 秒。禁止无限等待、禁止只加超时这两条都满足。
- 13 项点名字段逐条核对（`test_backend_autostart_diagnostics_v101.py` 3 例全过）：

| 任务单要求 | 诊断输出 |
|---|---|
| task_id / goal_id / run_id | `task_id=` / `goal_id=` / `run_id=`（无 run 行时写「（无）」） |
| task.status / run.status | `task.status=` / `run.status=` |
| dispatch.decision / dispatch.auto_start | `dispatch.decision=` / `dispatch.auto_start=`（快照 > 设置 > 兜底） |
| provider_id | `provider_id=` |
| 最近 20 条 AgentEvent | `select(...).limit(20)` + 「最近 N 条事件（新→旧）」逐条 seq/type/payload |
| runner 是否存在 | `worker.started` / `inprocess_runner.enabled` / `inprocess_runner.started` |
| runner 最后心跳 | `run.last_beat=run.updated_at`（并注明口径） |
| 当前 pending asyncio task | `pending_asyncio_tasks=` + 任务名列表 |
