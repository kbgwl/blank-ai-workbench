# 自学习：现在长什么样（2026-11-19 定稿）

前置阅读：`self-learning-diagnosis.md`（改之前的体检）、`self-improvement-methods.md`
（方法论调研）、`self-learning-reference.md`（开源实现调研）。

这份只讲**已经落地的东西**和**为什么这么做**。代码在 `services/agent/experience.py`。

---

## 一句话

一条经验 = 一个具体的坑或做法 + 什么时候该想起 + 凭什么信它。
学得少、学得准、用得克制、用完回溯——四件事都做到，才有资格叫自学习。

---

## 四条不变量（改代码前先看这节）

### 1. 形状：子任务级，不是任务总结

我们原来写的是整任务总结（「结果：结论 - 顶层共 31 项…」）。实测（2604.27003 /
2608.20274）：**整任务总结负迁移，低于"完全没有记忆"的基线**。所以形状必须换。

一条经验长这样：

```yaml
statement: "run_tests 跑 npm test 会超时"        # 具体的坑/做法
kind: pitfall | procedure | fact
trigger_paths: ["deliverables/**"]              # 什么时候该想起（硬信号）
task_terms: ["pagination"]                      # 加权，不单独触发
error_signature: "命令超过时间限制"               # 硬信号
evidence: [{task, signal, pointer}]             # 凭什么信它，必须能指向具体东西
confidence: 0.5                                 # 0.3–0.9，永不写 1.0
status: candidate | active | retired
hits / misses                                   # 被用过的次数与结果
```

### 2. 准入：没东西可学就返回 0 条

| 场景 | 学吗 | 理由 |
|---|---|---|
| 冒烟 / 纯只读任务 | ❌ | 没有可复用的东西。**这类占我们旧记忆的 79%** |
| 改了文件但没验证 | ❌ | 不知道对不对，写成"能成"是最危险的假阳性 |
| 失败但没有可定位信号 | ❌ | 只是"感觉不对"，据此写经验就是幻觉 |
| 失败且有报错/退出码 | ✅ pitfall | 一次踩坑的价值通常高于一次顺利 |
| 改动且验证过 | ✅ procedure | 有事实支撑 |

"这次学到 0 条"是正常结果。看事件 `experience.learned` 的 `count` 就知道。

### 3. 剂量：一次只注入 1 条

SWE-Exp 的 k 消融：**1 条 42.0 / 2 条 39.8 / 4 条 39.0**。多给只会互相干扰。

注入的措辞也不是随便写的：

```
[踩过的坑，来自本项目的历史任务，可能不适用，请自行验证] <statement>
依据：<signal>（<pointer>）
```

- 说"可能不适用"，**不说"必须遵守"**——后者会让模型放弃验证；
- **不要求引用或复述**（SWE-Exp：强制引用导致过度依赖，改成隐性上下文最好）；
- 位置在"任务目标"之后、第一次编辑之前（user 消息，不进 system）。

真正必须遵守的规则不走记忆，走 hook / lint / 审批。**记忆是上下文，不是 enforcement。**

### 4. 回写：用完要记账，而且要能退役

注入时把指纹记进 `turn_state["recalled_experience"]`；收尾时（成功和失败都算）回写。

| 结果 | 效果 |
|---|---|
| 成功 | `hits+1`，置信度 +0.05，攒够 2 次 → `candidate` 晋升 `active` |
| 失败 | `misses+1`，置信度 −0.12，攒够 2 次 → 退役，之后再检索不到 |

步长刻意不对称：成功可能是别的原因，失败也可能是它带偏了，但**代价更该被记住**。

没有这一环，条目永远停在 candidate，谁也不知道它有没有用——开源实现里普遍如此。

---

### 5. 失效：过期停止注入，成功才续命

`expires_after_days`（默认 90 天）原来只写在 dataclass 里、**没有任何代码读它**——
条目实际永不过期。规则照 Copilot Memory：**只有 upvote（用成功）重置，单纯被检索不重置**。

最后半句是关键：如果"被检索到就续命"，一条老经验只要还挂在触发条件里就能无限活下去，
哪怕它早就不成立；而它每次被注入，模型都会当"历史经验"照做。

缺时间戳或解析不出来时**判不过期**——宁可多留一条，不要因为缺一个字段误杀。

## 零、两个层：学世界 vs 学人

上面四条讲的是**学世界**（`services/agent/experience.py`）：这里会怎么坏、哪条命令能验。
它回答"这里会怎么坏"，靠路径与报错签名触发。

下面要讲的是**学人**（`services/agent/persona.py`）：他怎么干活。两者不能混。

| | 学世界 | 学人 |
|---|---|---|
| 回答 | 这里会怎么坏 | 他会怎么做 |
| 原料 | 工具失败、退出码、改动路径 | **他自己说过的话** |
| 触发 | 路径前缀 / 报错签名（"这次会遇到"） | 工作维度（"这类事他一贯如此"） |
| 学歪的形态 | 把个案当通则，过度规避 | **把 agent 的猜测当成他的偏好，替他决定** |
| 判据 | 同一个坑有没有重复踩 | 交付像不像他做的、他要不要返工 |

混在一起的后果很具体：把"npm test 会超时"塞进使用者模型，模型会读成
"他不喜欢跑测试"——**这是两种完全不同的结论，后者是灾难性的误读**。

## 生命周期

```
            准入通过 + 抽取
                   │
                   ▼
              candidate ──── 成功 ≥2 ────► active ──── 失败 ≥2 ────► retired
                   │                        │                          │
                   └──── 失败 ≥2 ───────────┘                     不再被检索
                                                                   （保留可追溯）
```

去重在写入侧：同一句话 → `confirmed`（涨置信度）；同一报错签名但结论不同 →
`replaced`（旧的退役）。**同主题只能有一条现行版本**——两条矛盾记忆同时被检索到，
遵从后成功率 17–31%。

## 三个入口

| 目的 | 命令 / 位置 |
|---|---|
| 学（自动） | 任务收尾，`_consolidate()` → `extract()` → `Store.record()` |
| 用（自动） | 任务开始，按目标 + 从目标认出的路径检索 1 条 → 注入首轮 user 消息 |
| 验 | `python scripts/repeat_mistakes.py --db <库>` 算 `repeat_mistake_rate` |
| 体检 | `python scripts/lint_experience.py`（过载 / 矛盾 / 低质 / 卡住 / 过期） |
| 纠偏 | `lint_experience.py --retire-id`（这条）/ `--retire-path`、`--retire-kind`（这类）/ `--retire-all` |

**负反馈必须能分层**。只有"删单条"时，agent 学歪一类任务就得一条条删，删到第五条
用户就烦了——烦了之后他不删，而是把整个功能关掉（Copilot/GitLab Duo 的教训：
关掉记忆不删数据、删掉的推断 30 天复活，信任就是这么崩的）。

**什么都不传就什么都不做**：退役是破坏性操作，不接受"没指定 = 全选"。
**退役不是删除**：条目还在文件里，只是不再被检索，lint 仍能看到它。

## 明确不做的事（每条都有原因）

| 不做 | 为什么 |
|---|---|
| **用模型反思来抽取** | ExpeL 把 reflection 加进抽取：39 → 29；Reflexion 去掉测试只留反思：0.52 < 基线 0.60。自反思写出的经验听起来对、实际是幻觉 |
| **自动生成 / 维护 AGENTS.md** | ETH Zurich 2602.11988：无显著提升，成本 +20–23%，步数 +2.45–3.92 |
| **自动删记忆** | 一条错记忆被自动删掉用户不会知道；留在库里至少能被 lint 报出来 |
| **靠"关掉记忆"防污染** | 2610.04083：拿掉 memory 工具后 74% 的会话改用文件系统，审计器也只能把传播率从 71% 降到 34% |
| **注入多条经验** | 剂量消融见上 |
| **语义相似检索** | 显式 trigger（路径/签名）可解释、可调试；向量相似度在"为什么想起这条"上给不出答案 |

## 验收口径

`repeat_mistake_rate = 跨 ≥2 个任务的失败签名数 / 失败签名总数`

口径三条：只算 `tool.completed` 且 `ok=false`；**`denied` 不算**（审批在正常工作）；
签名先去数字/路径/引号内容再比。

当前基线：**0.25**（29 次失败 / 16 个唯一签名 / 4 个跨任务重复）。

**脚本在签名数 < 20 时会打印"不要拿它做前后对比结论"**。这不是客套：我试过按
"慢命令记忆上线"切时间对比，机制后 0.5 反而高于机制前 0.071——因为机制后只剩
6 次失败、4 个签名，分母小到任何新签名都能把比率翻倍。宁可说样本不够，不给假结论。

## 学人：使用者模型（`services/agent/persona.py`）

### 唯一必须守住的不变量

> **只有用户自己说过、写过的东西才能进使用者模型。**

最容易跑偏的路是从 agent 的成功反推偏好：偷懒跳过测试 → 任务成功 → 归纳出"他喜欢快"
→ 下次跳更多。这就是"越学越跑偏"的机制——它把 agent 自己的偷懒学成用户的偏好，
再用自己的偏见喂养自己。2610.04083 已证明"关掉记忆"挡不住这条路，只能从源头堵：
**每条偏好必须挂一句用户原话**，没有原话就不准入。

### 三条次一级约束

1. **一次不算数，而且必须是另一个任务**。同一个任务里重试两次不等于"他一贯如此"，
   那是自问自答。第一版只计数不看来源任务，一次任务内重放两次就能顶成 active。
2. **两条打架就都不用**。同一维度、方向相反、且说的是同一件事 → 两条都停用，
   报出来让人定。不是让模型自己挑：实测两条矛盾记忆同时被检索时遵从率 63–72%，
   遵从后成功率塌到 17–31%（2607.10608）。判"同一件事"用字符二元组重叠——
   "必须跑测试" 与 "不要跑测试" 共享 {跑测, 测试}，而"不要调用任何工具"与
   "参数 command 必须是这一条"一个都不共享（它们来自两段不相干的脚本，不打架）。
3. **与本次明确指示冲突时以本次为准**。写进注入文案。把它当硬规则，agent 就会固执
   ——那是漫画，不是像他。

### 两个来源，晋级规则不同

| 来源 | 入口 | 置信基础 | 能不能自己生效 |
|---|---|---|---|
| **他明说的** | 驳回时写的理由 | 他亲口说"为什么" | 两个不同任务里出现即生效 |
| **从任务描述里摘的** | `scripts/persona.py --harvest` | 只能看出重复 | **永远要人确认** |

第二条是拿 111 个真实任务描述试出来的教训：任务描述写的是"这一次要做什么"。
不加限制时它把冒烟脚本里的 `必须用 run_shell 执行 echo smoke-ok` 学成了"一贯要求"，
还因为同一段脚本跑了 30 遍而晋级。**重复不等于一贯——得看重复的是不是同一个人的
同一个意图。** 所以运行时**不从任务描述学**，那条路改成低频、显式、只出候选。

### 失效与续期

`expires_after_days`（默认 180 天）**有人读**。规则照 Copilot Memory：只有
"在另一个任务里又出现了"才续期，**被注入本身不续期**——否则他早换了做法，
我们还在按两年前的规矩办，那时它就不是"像他"，是"像过去的他"。

没有 `hits/misses` 回写，这是刻意的：使用者模型是**常驻上下文**，任务成败无法归因到
某一条偏好上（而坑至少还能说"用了这条、那步过了"）。真正的负信号是"两条打架"——
它立刻停用，比统计更准。

### 可见与可撤

调研里最一致的一条：**能让人信任的自学都是白盒**。所以：

    python scripts/persona.py            # 它学了我什么（每条附我当时说的原话）
    python scripts/persona.py --lint     # 冲突 / 无原话 / 过期 / 未确认
    python scripts/persona.py --promote <指纹>   # 这条确实是我的一贯要求，生效
    python scripts/persona.py --retire <指纹>    # 这条不对，别再用了

退役不是删除：条目还在文件里，只是不再被注入。删掉之后连"它曾经学错过什么"都不知道了。

### 度量"像不像他"

`repeat_mistake_rate` 量的是"少犯错"，不衡量"像他"。像不像他看三个数
（`python scripts/persona.py --report`）：

- **驳回率** = 驳回 / (驳回 + 批准)：他在拦我多少次；
- **需要解释的驳回占比** = 带反馈的驳回 / 驳回：**这个数越高说明我越不懂他**——
  如果我知道他要什么，他点一下"不允许"就够了；
- 有结论的任务数。

两个数要一起看：驳回率降到 0 不一定好，可能是他懒得管了。

## 已知缺口

- **同 thread 的后续追问还没接**：那才是"工序"的主要来源（他在任务跑完后补一句
  "下次先跑单个测试再跑全量"）。现在只接了驳回理由，因为追问的事件形态还没摸清
  （`message.added` 里查不到 user 消息）。
- **偏好的作用域只到项目**：跨项目的偏好（"他从不用 tab 缩进"）现在要每个项目各学一遍。
  要升级成全局，得先有人确认——按上面那条"重复不等于一贯"，这一步不能自动。

1. **样本不足**：16 个签名，离能做对比的 20 差一点。需要多跑真实任务。
2. **语义矛盾检测**：lint 只能粗判"要 / 不要"，真正的语义冲突需要模型判断。
   而现在不做模型判断是刻意的（见"明确不做"第一条）。
3. **跨项目经验**：现在按工作区隔离。同类项目之间的共性（比如"这个模型不爱用工具"）
   无处沉淀。这是刻意的保守——跨项目共享是污染扩散的最短路径。
