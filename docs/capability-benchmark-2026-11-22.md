# 能力对标：空白格 / Claude Code / Codex（2026-11-22）

> 目的：用同一组任务、同一套隐藏验收、同一套判分，回答“我们的内核现在到底
> 处于什么水平”。结论只来自真实运行，不以交付文本自述为准。
>
> 运行环境：Windows 11，后端 `127.0.0.1:8065`（本次专用实例），
> 前端与主服务未参与评测。我们使用 DeepSeek 供应商；Claude Code 的实际
> 模型是 `deepseek-flash[1m]`；Codex 因账号/模型不可用，未能完成任何任务。

## 一、结论

1. **四个任务我们和 Claude Code 都 4/4 通过**：正确性、命中文件、最小改动
   三项全部拿到；我们平均分 **96.5**，Claude Code **97.5**（满分 100）。
2. **主要差距在成本，不在能不能做对**：我们平均 **225K token/任务**，
   Claude Code **128K**，约为 1.76 倍；T25 文档任务差距最大（399K vs 138K，
   约 2.9 倍）。
3. **速度基本持平**：平均都是 25 秒/任务；我们在 T01/T03/T07 更快，
   T25 更慢（43s vs 29s）。
4. **轮次更少、单轮更重**：我们平均 10.25 轮，Claude Code 13.25 轮；
   省了往返，但每轮携带的上下文更多，token 总量反而更高。
5. **Codex 本次不可用**：默认免费模型返回 404，显式使用配置里的
   `gpt-5.6-luna` 返回 402（额度不足）。因此 Codex 没有有效成绩，
   不能写成“0 分”或“能力为零”。

## 四、本次踩到的真实缺陷与修正

### 4.1 我们自己的指令误判（已修复）

T03 第一次运行我们 **0 个文件改动、25 分**。原因不是模型不会修，而是用户
原话里的 **“不要改变对外 API 名称”** 被旧的 `_NO_WRITE` 正则用裸“改”
匹配成了“不要改代码”，整轮被锁成只读。模型正确指出了
`"./mathy"` 缺 `.js`，但执行层不允许写。

修复：`_NO_WRITE` 不再收裸“改”，只认“修改/改动/改写/改代码/改文件/
改实现”等明确说法，并补了回归测试。修复后同一任务单跑 **100 分、
1 个文件改动、13 秒**；最终四任务里为 95.8（成本项略低于 Claude）。

### 4.2 无目录动作任务被误当成纯聊天（已修复）

回归测试 `test_unbound_workspace_stops_the_dispatcher_before_any_run` 发现：
没有绑定目录时，“做一个官网”这种明确动手任务被 `chat_only` 放行自动执行，
而不是 `wait_user`。现在 `workspace_bound` 只在“纯聊天且不执行”时豁免目录；
动作任务仍要求先选目录。

### 4.3 评测自身的假分数（已修复）

- T03 fixture 原来“看起来坏、实际能跑”：`export { pct as percent } from
  "./mathy.js"` 语法本身合法，基线是绿的；改成真正缺 `.js` 的 `"./mathy"`
  后才有正确的失败信号。
- T01/T07/T25 原来只跑 fixture 自带测试，改 README 也可能“测试通过”；
  现在注入隐藏验收。
- 我们的 `.blank/` 内部记账文件原来被算成“多余改动”，无端扣最小改动分；
  现在与 `.blank_backups` 一样忽略。
- 评测工作区移到仓库外，Claude/Codex 不会再读到本项目的 `CLAUDE.md` /
  `AGENTS.md`；Claude 用 `--safe-mode` 关闭用户级定制；Codex 显式给
  `workspace-write` 沙箱。

## 五、Codex 为什么不可用

两次独立探测：

```text
默认免费模型：
404 Not Found: This model is unavailable for free.
use this slug instead: nex-agi/nex-n2.5-pro

显式 -m gpt-5.6-luna：
402 Payment Required: can only afford 3068 tokens
```

这属于账号/模型配置问题，不是 Codex 能力结论。要恢复对比，需要：
1. 换一个可用的 Codex 模型或充值额度；
2. 在 `compare.mjs` 里传入对应模型；
3. 重跑同一组任务。

## 六、边界

- 只有 4 个小任务，覆盖编程、修 bug、数据、文档，不代表大型多文件项目。
- 我们的模型是 `deepseek-flash`，Claude Code 是 `deepseek-flash[1m]`；
  同一模型家族，但不是严格同模型/同端点。
- Claude Code 的自证分只能从最终文本判断；T25 它实际通过隐藏验收，但文本
  未提测试命令，自证记 0，因此 90 分是**下限**，不是能力差距。
- 隐藏验收由我们编写，可能存在实现偏好；下一步应加入独立任务或人工盲评。
- 本轮没有跑浏览器/桌面应用类任务；生成页面的真机质量仍以 D2/C6 的
  browser_check 为准。
