# 空白格 AI 操作台 · 桌面应用设计规格

> 可视稿：`docs/app-mockup.html`（浏览器打开，可切屏、切明暗、按 `Ctrl K` 看命令面板）
> 截图：`E:\downloads\appshot\*.png`

## 1. 目标产物（已定）

**Windows x64 上双击即用的自包含 .exe。** 目标机不需要装 Python、Node、Docker 或任何运行时。

两种交付形态：

- **`空白格-安装版.exe`**（NSIS 安装包）：常规分发，建快捷方式、支持覆盖升级
- **`空白格-便携版.exe`**（单文件）：内测 / 免安装，双击直接跑

数据落 `%APPDATA%\blank-workbench\`（SQLite、快照、artifact、日志）；本机开发仍可用 `BLANK_HOME` 指到 E 盘。

## 2. 壳选型：Electron（更正上一版结论）

上一版我推荐 Tauri，**只算了体积没算工具链成本，这个判断是错的**。实测本机：

| | **Electron** ✅ 采纳 | Tauri |
|---|---|---|
| 需要新装的工具链 | **无**（本机已有 Node 24） | **Rust + MSVC C++ Build Tools** |
| 该工具链代价 | — | 多 GB，且大量写 C 盘（与 E 盘铁律冲突） |
| 渲染依赖 | 自带 Chromium，**目标机零依赖** | 依赖目标机 WebView2（本机有，Win LTSC / 老 Win10 可能没有） |
| 安装后体积 | 约 150–200MB | 约 10MB |
| 内存 | 较高 | 低 |
| 与团队栈的匹配度 | 同一套 JS/TS | 需额外维护 Rust 壳代码 |

**结论：用体积换零工具链成本，选 Electron。** 若日后体积/内存真成痛点，再评估迁 Tauri —— 界面代码可原样复用，迁移不白做。

否掉的其余路线：PWA（已明确否决）；移动 App（够不着本机仓库 / shell / 沙箱 / 工作区路径，那是另一个产品）。

### 2.4 关于「原生 exe」：先把两个问题拆开

「原生」这个词常把两件不同的事搅在一起：

| 问题 | 含义 | 现状 |
|---|---|---|
| **交付物是不是 exe** | 双击能跑、目标机不装浏览器 / 运行时 | ✅ **已经是**。Electron 产出独立 exe、自带 Chromium、目标机零依赖 |
| **界面用什么画** | 系统原生控件 vs web 渲染 | 目前是 web 渲染（内核随包带走） |

判断一个桌面应用"是不是原生"，行业里的标准是**交付物形态和依赖**，不是"用什么描述界面"。主流桌面产品基本都是「exe + web 渲染」：VS Code、Cursor、Slack、Discord、Figma、Notion，以及 **WorkBuddy 自身**（Electron 37，实测其进程 User-Agent 可见）。所以这不是偷懒，是这一代桌面应用的主流做法。

### 2.5 如果确实要「系统原生控件渲染」

能做到，但代价是**重写整个界面**：

| 路线 | 自包含体积 | 重写量 | 主要风险 |
|---|---|---|---|
| C# / WPF 或 WinUI 3 | ~70MB | 全部界面 | 后端仍是 Python，要单独打包；需要 C#/XAML 技能 |
| Rust + egui | ~8MB | 全部界面 | 立即模式 GUI 做三栏 / diff / 时间线很费劲，控件生态少 |
| C++ / Qt | ~40MB | 全部界面 | 构建链复杂；Qt 授权 |
| Python + PySide6 | ~100MB+ | 全部界面 | 打包体积大；LGPL |

**判断：不建议。** 这个产品的界面是**数据密集 + 高频迭代**（时间线、diff、审批卡、场景），恰好是原生控件栈开发效率最低的形态；而且现有前端已有 6,847 行，重写等于把已有设计与交互全部作废。

### 2.6 如果诉求是「体积小、启动快」（而不是「原生控件」）

那答案是 **Tauri**：交付物同样是真 exe，但用系统 webview 渲染 —— 体积约 10MB（比 Electron 小一个数量级）、内存更低。**前端代码可原样复用**（同样的静态导出），只需用 Rust 重写外壳那一层。

唯一门槛：装一次工具链 —— **Rust + MSVC C++ Build Tools**（多 GB，且大量写 C 盘）。

**所以真正的决策点是：你要的是「体积小」还是「系统原生控件」？**

- 体积小 → 迁 Tauri，界面不白做
- 系统原生控件 → 重写界面，不推荐
- 只是"必须是能双击的 exe、不像网页" → **Electron 已经满足**

## 3. 静态导出：已实测可行

`next build` + `output: "export"` 实测结论：

- ✅ **12 个页面全部预渲染成功**，产出完整静态 `out/`
- ❌ **唯一拦路石**：`/tasks/[id]` 缺 `generateStaticParams`，而任务 ID 是运行时产生的、无法预生成 → 报 `Page "/tasks/[id]" is missing "generateStaticParams()"`
- 改造面很小：**只有 4 处**构造 `/tasks/${id}` 链接（`brainstorm/page.tsx`、`chat-home.tsx` ×2、`task-console.tsx`）

**修法**：任务详情从路径参数改为查询参数 `/tasks/detail?id=xxx`（客户端 SPA 本来就不需要路径段）。改完静态导出即通。

同时要改：

- 去掉 `next.config.ts` 的 `/api/*` rewrite（静态导出不支持 rewrite）。前端 API 基址改由 `NEXT_PUBLIC_API_BASE` 决定：网页/开发态留空走相对路径，桌面构建填 `http://127.0.0.1:8000`
- 后端 CORS 放行桌面壳来源
- `globals.css` 里已有成套令牌（`--bg/--surface/--line/--text/--accent/--brand`），**沿用，不推倒重来**

## 4. 后端必须一起打包（不是可选项）

自包含 exe 的前提是后端也进包。后端是 Python（FastAPI + LangGraph）。

**关键证据**：实测 WorkBuddy 5.8.2 的安装目录 —— 它**自带一整套完整 CPython 3.13.14（53MB）**，
而不是用 PyInstaller 打成一个二进制。这给了我们一条风险低得多的路线：

| 方案 | 体积 | 风险 | 结论 |
|---|---|---|---|
| **整包携带完整 Python 运行时**（照抄 WorkBuddy） | +约 53MB | **低**。依赖树与开发环境一字不差，`python.exe -m uvicorn` 直接跑 | ✅ **采纳** |
| PyInstaller `onedir` | +40~80MB | 中高。LangGraph / pydantic 这类动态导入多的栈经常漏模块，要反复补 hiddenimports，失败模式是"打包成功但运行时缺模块"，排查成本高 | 备选 |
| 目标机已有 Python / uv | 0 | — | 只作**开发期过渡**，不作为交付形态 |
| 后端改写 Rust / Go | — | 重写量大，放弃 LangGraph 生态 | 不推荐 |

**为什么改推「自带 Python」**：多花 53MB，换**零打包风险** —— 依赖与开发环境完全一致，不需要维护一份
随时会烂的 hiddenimports 清单。对一个还要持续迭代的产品，这个交易是划算的。

打包要点：随包携带运行时 + `services/api` 源码与 `.venv` 的等价依赖；alembic 迁移在首次启动时执行；
由壳拉起 sidecar 并做健康检查。

## 5. 应用外壳规格

```
┌ 标题栏 46px  品牌 · 工作区选择 · ⌘K 搜索 · 主题 · 窗口控件 ┐
├ 导航 196px ┬ 主工作区 flexible ────────────┬ 检查器 300px ┤
│ 工作        │ 头部（任务标题/状态/步数/成本）│ 文件·变更·证据│
│  对话 ●     │ 时间线（计划/工具/审批/终端）  │              │
│  概览       │ 输入区（补充要求 / 继续）      │              │
│  项目       │                                │              │
│ 工具        │                                │              │
│  头脑风暴…  │                                │              │
├────────────┴────────────────────────────────┴──────────────┤
│ 状态栏 28px  本地服务 · 沙箱 · 模型 · 本次成本 · 版本        │
└──────────────────────────────────────────────────────────────┘
```

- **自绘标题栏**（`decorations: false` + 可拖拽区），去浏览器感、去"网页味"
- **窗口**：默认 1280×800，最小 1024×680；记忆上次尺寸与位置
- **托盘**：常驻；后台运行时可从托盘快速新建任务
- **全局快捷键**：`Ctrl+Shift+Space` 唤起主窗口并聚焦输入框
- **系统通知**：任务完成 / 等待审批 / 运行失败 —— 三种，都可单独关
- **单实例**：重复启动时聚焦已有窗口，不新开

## 6. 导航重构（从"页面"改成"工作面"）

现有 7 个平铺入口（概览/对话/头脑风暴/日常/逆向/功能/设置）是**网站式**的信息架构。应用里按**使用频次 + 任务属性**分成两组：

- **工作**：对话（主工作面，默认落地页）· 概览 · 项目
- **工具**：头脑风暴 · 日常 · 逆向实验室 · 功能中心
- **底部**：设置

配套的"快"是应用的核心体验：**`Ctrl K` 命令面板**（新建任务 / 切工作区 / 导出证据包 / 回滚快照 / 打开设置），**`Ctrl N` 新建任务**，**`Ctrl P` 切工作区**。

## 7. 设计系统

### 5.1 色彩（浅色优先，暗色是同一套令牌的变量覆盖）

| 令牌 | 浅色 | 暗色 | 用途 |
|---|---|---|---|
| `--bg` | `#f5f6f8` | `#0e1116` | 应用画布 |
| `--surface` | `#ffffff` | `#151a21` | 面板/卡片 |
| `--surface-2` | `#f0f2f5` | `#1b2129` | 次级面、hover |
| `--line` / `--line-strong` | `#e4e7ec` / `#d0d5dd` | `#252c36` / `#333c48` | 分隔线 |
| `--text` / `--muted` / `--faint` | `#16181d` / `#5b6472` / `#8b94a3` | `#e7eaee` / `#9aa4b2` / `#6c7480` | 三级文字 |
| `--accent` | `#0e7490` | `#38bed4` | **唯一强调色**（青 = AI 色） |
| `--ok` / `--warn` / `--danger` | `#15803d` / `#b45309` / `#b42318` | 提亮版 | 语义色，仅用于状态 |

规则：**除强调色与三个语义色外不加彩色**。层级靠灰阶 + 1px 描边，不靠阴影堆叠。

### 5.2 字体与尺度

- 正文 `13px / 1.5`；标题 `15px / 650`；元信息 `11px`；代码 `11px` 等宽
- 系统字体栈（`-apple-system, Segoe UI, PingFang SC`），代码 `ui-monospace/JetBrains Mono`
- 间距刻度 `4 / 8 / 12 / 16 / 24 / 32`；圆角 `7px 控件 · 10px 卡片 · 12px 窗口`；两档阴影

### 5.3 组件与状态

- **状态徽标**：运行中（青）/ 已完成（绿）/ 待批准（琥珀）/ 失败（红）/ 停用（灰）
- **步骤节点**：完成（实心勾）/ 进行中（呼吸光标）/ 待批准（时钟），三种形态一眼可分
- **审批卡**：必须写清「哪个工具 · 哪个文件 · 只绑定本次参数 · 多久过期」——这是本产品相对纯 CLI 的信任基础
- **必备状态**：空态、加载骨架、错误、**后端未启动**（专屏，给"重启服务 / 看日志 / 改用手动地址"三个出口）

### 5.4 可达性

- 全部可 Tab 到、焦点态用强调色 3px 外发光；`Esc` 关面板；`Ctrl K` 开命令面板
- 文字对比度按 WCAG AA；不用纯色块传递唯一信息（状态徽标都带文字）

## 8. 与"主流"的对标取舍

对标 Linear / Claude / Vercel 这一代：**浅色打底、单一强调色、极简线性图标、克制留白、命令面板优先**。三处刻意不跟随：

1. **不做"聊天气泡"** —— 这是工程执行台，不是聊天软件。计划、工具调用、终端、审批按**步骤**纵向排布，一眼能看出"它到底做了什么、证据在哪"
2. **保留右栏检查器** —— 主流聊天产品没有它。Diff 与证据必须同屏可见，这是可追责性的可视化
3. **审批卡做重、不做轻** —— 主流产品把危险操作做成一个小确认框；我们把它做成一张带参数的卡片

## 9. 实施路线

顺序是刻意的：**先把"能不能装成 exe"这条链打通，再美化界面** —— 否则样式做完才发现装不进去，白做。

1. **前端静态化**（已实测可行）：加 `output: "export"`；`/tasks/[id]` 改查询参数（4 处链接 + 路由文件）；去掉 `/api/*` rewrite，API 基址改由 `NEXT_PUBLIC_API_BASE` 决定；后端 CORS 放行桌面壳来源
2. **Electron 壳跑起来**：主进程 + 窗口（自绘标题栏、最小尺寸、记忆位置）、托盘、全局快捷键、单实例；先加载静态 `out/` 验证界面完整
3. **后端进程守护**：探测 8000 端口 → 未就绪则拉起 sidecar → 健康检查 → 崩溃重启 → 失败进"服务未启动"专屏
4. **套设计系统**：令牌固化进 `globals.css`，先换外壳（标题栏 / 导航 / 状态栏），再逐屏替换
5. **后端打包**：PyInstaller `onedir` 出 `blank-backend.exe`，写 spec 收纳 alembic 与 LangGraph 隐藏导入
6. **出包**：`electron-builder` → 便携版单 exe（内测）+ NSIS 安装包；配图标、版本号、覆盖升级
7. **工具链落 E 盘**：Electron 二进制缓存默认落 C 盘，用 `ELECTRON_CACHE=E:\env\electron-cache` 引走；构建产物落 `E:\downloads\`

**风险顺序**：PyInstaller 打包后端 > 进程守护行为 > 静态导出后的客户端路由 > 纯样式替换。

**验收口径**（可追责）：

- 在一台**没装 Python / Node / Docker** 的干净 Windows 上，双击 exe 能进界面并跑通一次任务
- 冷启动到可交互 < 3s（PyInstaller 解压是主要变数）
- 后端未启动或崩溃时，界面给可操作出口而不是白屏
- 同机重复启动只有单实例
- 所有危险操作在应用内都能看到"绑定了哪些参数、何时过期"
