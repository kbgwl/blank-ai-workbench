# bot 和 agent 的区别

> 为什么把产品从「智能体操作台」改成「空白格 bot」，内核却一点没变——
> 这两个词根本不在同一个轴上。一个说的是**表面**，一个说的是**控制结构**。

## 一句话

**bot 是交互形态，agent 是运行时机制。** 前者回答"你在跟谁说话、以什么节奏"，
后者回答"下一步是谁决定的"。两者可以任意组合，所以「bot 还是 agent」这个问法
本身就问错了——我们在做的是一个 agent 内核套 bot 表面。

## 两个词各自的来历

**bot**：从 robot 缩来，最早指 IRC/QQ 上的自动账号，后来 = chatbot（问答机器人）。
它描述的始终是**人面对的那个东西**：有个名字、能对话、在对话框里回你话。
它不承诺任何执行能力——早期的 bot 是关键词匹配 + 预设脚本，今天的大多数 bot
是"一次 LLM 调用 + 流式吐字"。

**agent**：来自 AI 里的智能体概念（感知–决策–行动），在 LLM 时代被重新定义。
Anthropic 在《Building effective agents》里给的分法是目前最清楚的：

| | 谁决定下一步 | 典型形态 |
|---|---|---|
| **workflow（工作流）** | **代码**：LLM 与工具按预设路径编排 | 提示链、路由分发、并行汇总 |
| **agent（智能体）** | **模型**：运行时自己决定走哪条路、调哪个工具 | 代码代理、自主任务执行 |

同一篇文章里那句更短的定义：agent 就是"**LLM 在循环里、根据环境反馈使用工具**"。
循环来自 ReAct（Yao 等，2022）：思考 → 行动 → 观察 → 再思考，直到它自己判断做完了。

Anthropic 2026 年那份自主性研究把定义做得更能测量：agent 是**带工具、能真正采取行动**
（跑代码、调外部 API、给别人发消息）的系统，并直接拿 Claude Code 的**单轮时长**当
自主度指标——中位数约 45 秒，而 99.9 分位从 25 分钟涨到 45 分钟以上。
换句话说：**agent 的"自主"是可以按分钟计量的，bot 的"回合"按秒计。**

## 三条真正的判据

网上流传的对比表大多在比"有没有记忆、会不会调工具"，那些是**现象不是判据**——
写死链路的工作流照样调工具、照样有记忆。真正的分界只有三条：

1. **下一步是谁决定的。** 你能提前把流程图完整画出来 → 那是工作流。
   画不出来、必须看它跑到哪再决定 → 才需要 agent。
2. **有没有闭环。** 一次调用出结果就结束的是 bot；action 的结果必须回到模型
   再判断一次、可能推翻自己上一个决定的，是 agent。闭环也意味着**必须有停止条件**。
3. **失败由谁兜。** bot 出错靠用户重说一遍；agent 出错应该自己看报错、换个做法，
   兜不住才转人工。这一条决定了两者的成本结构和信任模型完全不同。

还有一条很实用的土办法（来自工程实践）：**把 LLM 抽掉，看还剩什么。**
bot 抽掉之后是空壳；工作流抽掉之后链路还在、只是没人做决策；agent 抽掉之后
工具和状态还在，但没人决定下一步——它已经不转了。

## 四个象限，不是一条鄙视链

| | **人给指令、模型只回话** | **模型自己决定下一步** |
|---|---|---|
| **对话框形态** | 传统 chatbot / ChatGPT 普通对话 | **Codex、Claude Code、空白格 bot** |
| **无对话形态** | API、批处理脚本 | 无人值守的循环任务（CI 修 bug、监控处置） |

右上角那一格是过去两年真正的变化：**表面还是聊天，控制权已经交给模型了。**
所以拿"它是 bot 还是 agent"来问 Codex 没有意义——它的界面是 bot，内核是 agent。

三种常见误判：

- **"会调函数的就是 agent"** 错。按固定链路调工具是工作流，可预测、可测试，
  很多场景这恰恰是更优解（Anthropic 的建议是"能简单就别上复杂"）。
- **"agent 一定更高级"** 错。agent 用延迟和成本换灵活性：同一条路径可能每次都不
  一样，出错方式也难枚举。任务本身能写死的时候，agent 是负担。
- **"bot 就是低级的"** 错。bot 说的是壳。壳的好坏决定人敢不敢用：看不看得见它在干什么、
  能不能打断、错了能不能回退。

## 落到空白格：哪层是 bot，哪层是 agent

**表面（bot）**：一个对话框、一条会话列表、右侧"这一轮动了什么"。它的义务是
**让人敢把控制权交出去**：

- 过程可见——工具调用、命令、改动文件按发生顺序摊开，而不是只给结论；
- 可打断——运行中按回车是插话（steer），不是再开一轮；随时能停；
- 高风险先问——写文件、跑命令按风险分级审批，独立审查（guardian）能直接否决；
- 会留痕——每一轮的决策、事件、改动都落库，事后能回答"为什么这么改"。

**内核（agent）**：`services/agent/graph.py` 里那个循环，模型自己决定调哪个工具、
按什么顺序、什么时候收工。它的义务是**别把控制权用坏**：

- 步数上限（`DEFAULT_MAX_STEPS = 200`）与收尾段（`WRAP_UP_STEPS = 3`）——
  跑到上限前先强制收口，不留下"事做一半、人也看不懂"的状态；
- 工具白名单与参数校验，工具结果必须回灌给模型再判断；
- 失败要能被自己看见（工具输出原样回到循环里），而不是吞掉；
- 停止条件明确：模型给出无工具调用的回复、被用户停止、被 guardian 拒绝、步数耗尽。

这正是我们把首页从"操作台"换成"对话"却不换内核的原因：**操作台是一种把 agent
当仪表盘用的界面，对话是把 agent 当同事用的界面。** 后者的信息密度更低，但
信任建立得更快——因为人只需要说目标，剩下的是看着它一步步做。

## 以后判断某个功能属于哪层

| 问题 | 属于壳（bot） | 属于内核（agent） |
|---|---|---|
| 这一步该不该让用户看见 | ✅ | |
| 这个工具该不该先审批 | ✅（策略） | ✅（执行时判定） |
| 下一步做什么 | | ✅ |
| 什么时候停 | ✅（用户能停） | ✅（步数/收工条件） |
| 错了怎么重来 | ✅（重发/分叉） | ✅（自己换做法） |

一条经验：**改壳的时候不要动内核的判断，改内核的时候必须同时想清楚壳怎么把它讲明白。**
循环里多一种状态（比如"它在等审批"），界面就必须多一种能看懂的表现；
否则用户看到的是"卡住了"，而实际上是"在等你"。
