## 2. P0：npm 和桌面干净环境安装

### 2.1 CLI 安装目标

目标命令：

```bash
npm install -g blank-ai-cli
blank-ai --help
blank-ai
```

如果产品最终命令不是 `blank-ai`，必须统一 README、package.json、bin 和安装文档，不允许出现多个入口名称。

### 2.2 CLI 检查项

检查 `packages/cli/package.json`：

- `name` 正确。
- `version` 与发布策略一致。
- `bin` 指向真实存在的入口。
- `files` 包含构建后文件。
- 入口文件有正确 shebang。
- Windows 下 `.cmd` 入口可用。
- 依赖没有引用工作区绝对路径。
- 安装后不依赖当前仓库目录。

执行：

```powershell
pnpm -C packages/cli test
pnpm -C packages/cli build
pnpm -C packages/cli pack --pack-destination .tmp-cli-pack
```

检查 tarball：

- 解压后可以独立运行。
- 不包含 `.env`、API Key、用户数据库和临时文件。
- 不包含绝对路径。
- 不依赖 `E:\projects\kbgai\kbgai`。

### 2.3 干净目录安装

创建新的临时目录，不使用当前仓库作为用户工作区。

验证流程：

1. 安装 CLI。
2. 执行 `blank-ai --help`。
3. 执行 `blank-ai`。
4. 检查服务端口是否启动。
5. 检查页面是否可以打开。
6. 配置一个模型。
7. 创建新对话。
8. 读取临时工作区文件。
9. 修改临时工作区文件。
10. 运行测试命令。
11. 查看任务结果。
12. 停止服务。
13. 再次启动并确认配置仍然存在。

必须记录：

- 安装命令。
- Node 版本。
- 操作系统。
- 启动耗时。
- 首屏耗时。
- 服务地址。
- 失败原因。

### 2.4 Desktop runtime

确认桌面端是否真正自带 Python runtime：

```powershell
pnpm runtime:desktop
pnpm verify:desktop
```

必须验证：

- 没有系统 Python 时是否能启动。
- 没有 uv 时是否能启动。
- runtime 是否包含 uvicorn、FastAPI、SQLAlchemy 等必要依赖。
- 后端源码是否被正确复制到安装包。
- 数据库是否写入用户数据目录，而不是安装目录。
- 密钥文件是否写入用户数据目录。
- 升级安装不会覆盖数据库和密钥。

如果仍依赖系统 Python，必须明确标记为未完成，不能写成“零依赖安装”。

### 2.5 P0 验收

## 5. P1：Agent 执行速度升级

### 5.1 减少无效调用

记录每轮：

- 模型调用次数。
- 文件读取次数。
- 重复文件读取次数。
- 工具失败次数。
- 重试次数。
- 上下文 Token。

优化：

- 相同文件片段短时间内缓存。
- 相同命令结果按工作区状态缓存。
- 搜索结果限制数量。
- 长输出保存 Artifact，只传摘要。
- 已经完成的步骤不重复执行。
- Agent 检测到目标完成后主动结束。

### 5.2 时间指标

目标：

| 指标 | 目标 |
|---|---:|
| 页面首次可交互 | ≤ 2 秒 |
| 场景切换 | ≤ 300ms |
| 模型切换 | ≤ 300ms |
| 小文件搜索 | ≤ 500ms |
| SSE 事件延迟 | ≤ 300ms |
| 工具结果展示延迟 | ≤ 500ms |
| 普通任务重复读取 | 0 次或可解释 |

不能为了速度跳过必要验证。

## 6. P1：上下文和长任务能力

### 6.1 上下文层级

统一为：

```text
系统规则
→ 场景规则
→ 用户目标
→ 仓库摘要
→ 当前文件片段
→ 工具结果摘要
→ 历史任务摘要
```

要求：

- 不发送整个仓库。
- 文件按需读取。
- 工具输出超限保存 Artifact。
- 长任务按阶段生成摘要。
- 上下文压缩后保留目标、已修改文件、测试失败原因。
- 场景记忆不能污染开发上下文。

### 6.2 长任务验收

构造一个至少 20 步的任务：

1. 读取多个目录。
2. 修改多个文件。
3. 运行测试。
4. 产生失败。
5. 自动修复。
6. 手动停止 Worker。
7. 恢复 Worker。
8. 检查是否重复执行工具。
9. 检查最终 diff。
10. 检查 Evidence。

验收：

- 不重复执行已经成功的 ToolCall。
- SSE 断开后可恢复。
- Worker 崩溃后可继续。
- 任务不会无限重试。
- 最终回复包含真实未完成项。

## 14. 最终原则

Blank AI 的竞争力不在于功能列表更多，而在于：

```text
更快完成任务
更少打扰用户
更少错误修改
更高测试通过率
更清晰的执行证据
更强的 DIY 能力
```

本阶段优先级必须是：

```text
真实安装 > 真实执行 > 任务完成率 > 模型路由 > Skill DIY > 记忆学习 > 更多页面
```

    新执行账的旧等待账视为陈账不挂卡；任务结束后改报「未获批准，未执行」。
  - 修复后：migration 5/5、cancel_resume 5/5（取消 5 秒内生效、零误修改）、
    unauthorizedHighRisk = 0、falseDoneCount = 0。

  单例复跑 PASS）；012/035 模型主动加测试属于未经要求的改动（如实计误修改）；
  034 步数耗尽真失败。
