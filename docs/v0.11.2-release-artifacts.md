#### 5.2.1 首轮回归的两条红：真缺陷，不是环境噪声

提交前、未改任何源码的首轮全量是 **2 failed / 2320 passed / 23 skipped / 726.34s / EXIT=1**：

- `tests/test_crash_resume_cross_process_v142.py::test_a_killed_worker_is_resumed_by_another_process`
- `tests/test_model_timeout_v35.py::test_the_timeout_is_actually_applied_to_the_client`

两条 traceback 都终止在同一处：`httpx.AsyncClient(...)`（`services/api/src/blank_api/services/models/base.py:78`）
抛 `httpx.InvalidURL: Invalid port: ':1]'`。根因在本机 `NO_PROXY`：

```
NO_PROXY=localhost,.localhost,127.0.0.1,127.0.0.0/8,[::1],::1
```

httpx 把 `NO_PROXY` 里的 `[::1]` 当普通主机名再套一层方括号（拼成 `all://*[::1]`），`URLPattern` 解析时抛错。
逐形态实测（httpx 0.28.1）：

| NO_PROXY | 结果 |
| --- | --- |
| 不设置 | OK |
| `[::1]` | **FAIL `Invalid port: ':1]'`** |
| `[::1]:8080` | **FAIL `Invalid port: ':1]:8080'`** |
| `[2001:db8::1]` | **FAIL** |
| `::1` / `127.0.0.0/8` / `localhost` / `.example.com` / `*` / `http://[::1]:8080` | OK |

A/B：只撤掉 `NO_PROXY` 再跑这两个文件 → `6 passed / EXIT=0`。**这不是测试写法问题**：用户机器只要 shell
里配了 curl 风格的方括号 IPv6 绕过，这个进程里每一条模型调用都会在构造客户端时炸掉。

#### 5.2.2 修法与判据

- 修在包入口 `services/api/src/blank_api/__init__.py`：把 `NO_PROXY`/`no_proxy` 里的 `[host]`、`[host]:port`
  归一成裸地址。httpx 会给裸 IPv6 自己补回方括号，绕过语义不变；端口一并去掉——httpx 表达不了
  「某 IPv6 的某端口绕过」，保留整台主机绕过比让整条规则把客户端构造炸掉更接近原意。
  模型池 / 消息通道 / CLI harness 三处 httpx 客户端因此一起受益，不逐个调用点改。
- 新增 `tests/test_proxy_env_v112.py` 3 例：纯函数逐形态、其它形态保持原样、**真子进程**在
  `NO_PROXY=localhost,[::1],127.0.0.1` 下 `import blank_api` + `pooled_client()` 构造成功且 mounts 含 `all://[::1]`。
- **判据能失败（实测）**：把入口那行 `_normalize_no_proxy_env()` 注释掉 → `1 failed / 2 passed / EXIT=1`，
  失败原因正是 `httpx.InvalidURL: Invalid port: ':1]'`；恢复后 `3 passed / EXIT=0`。
- 因 `src/` 有改动，安装包**重打**并重跑 44 项自检与更新源 10 步（§2 / §3 / §4.2 都是重打后的读数）。
