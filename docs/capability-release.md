# 把模型能力释放出来：我们自己的四条漏水管道

> 结论先说：这一轮的产出不好，**不是模型不够强，是我们自己的管道在漏**。
> 下面每条都带证据（事件号、字符数、提交），不是体感。

## 一、已修：附图在文本管道里被剪成半张

一条 3D 页面任务（`36d86ed2`）被判失败，交付里写着"浏览器里从未跑通"。
实际情况是页面好的——但模型没法看。造了 `browser_check` 之后又炸了三次：

| 现象 | 真实原因 | 代价 |
|---|---|---|
| 模型 400：`unsupported image` | 网关把工具结果里每个字符串削到 `MAX_RESULT_CHARS = 40_000`，59KB 截图的 base64 有 **79,620** 字符 → 只剩半截 data URI | 整轮失败，报错里看不出是被我们自己剪的 |
| 工具消息 20,025 字符 | 图片留在 `data.image` 里进了 `payload.render()`，撞上 `MAX_PAYLOAD_CHARS = 20_000` 被截断 | 每步重发 7k token 的残废 JSON × 步数 |

修法：图片在进任何文本管道**之前**就拎出来，走它自己的那条用户消息（`data.image` → 单独 message）；
网关的文本剪刀明确跳过 `image` 键。

- 判据：`tests/test_image_passthrough_v427.py`（3 条）
- 效果：工具消息 20,025 → **117** 字符；base64 一个字符不少
- 结果：同一个任务两步入终态，模型自己说出"左侧产线状态、中央 3D 传送带 7 台设备、右侧设备详情、底部统计"

## 二、已修：没有眼睛

模型要验证前端，手里只有 shell，于是起 electron 硬跑 WebGL——**连崩五次**（`36d86ed2` 事件
`run_shell failed ×5`），最后把"请你自己打开确认"写进交付。

新增 `browser_check`：打开页面 → 收控制台错误 → 按选择器断言 → 截图（截图作为图片附给模型）。
边界写在代码里：只允许工作区内文件与 `localhost/127.0.0.1`；截图只能落 `.blank/shots/`。

它同时是**评分器**：同一句话跑两个模型，"页面能不能渲染 + 控制台几条错 + 关键元素在不在"是客观分。
"谁家模型强"从此不用吵。

## 三、已修：超时被写成"测试未通过"

`npm test` 在这个仓库是**全量后端单测，约 25 分钟**，单次上限 180 秒 → 必然超时；
而 `_failure_reason` 把 `timeout` 落进了"测试未通过"，修复回路据此让模型"改最小范围"。
一个能跑的页面就这样被判失败。

修法：超时单列一支（文案说清"多久没跑完、这不是失败"）；修复指令改指"换一条跑得完的验证路径"；
验证事件补 `summary`，时间线不再是个空壳。

## 四、还没治的（按收益排）

1. **上下文单调增长**。26 步里 prompt 从 19k 涨到 83k（累计 1.79M token）。压缩阈值是
   `0.82 × context_window(1M)`，实际上永远不触发——于是模型每一步都在重读自己的全部历史，
   其中大半是它自己刚写的文件内容。**该给的是当前状态的快照，不是全部历史。**
2. **没有进展哨兵**。同一份 `gl.js` 被重写 6 次、同一条 `dir` 命令跑了 9 次、同一个 `edit_file`
   锚点改了 3 次，全部 `ok`，没有任何一处提示"这一步没有产生新证据"。26 步里真正干活的只有前 6 步。
3. **输出上限 8192 token**。这一轮没撞上（最大 6040），但它是天花板：大文件一次写不完，
   模型只能分片重写——正好是第 2 条里那种打转。
4. **推理档未启用**（`reasoning_effort` 为空）。代码任务上，思考档通常是便宜的收益。

## 五、可复用的原则

- **二进制不进文本管道**：图片、音频、PDF 各走各的通道。凡是"先当字符串处理再拼回去"的设计，
  都会在某个上限处把它剪断，而错误现场往往看不出是剪切造成的。
- **剪裁必须自解释**：说清剪了多少、怎么拿全。静默截断比截断本身更坏。
- **能力释放 = 减少它必须猜的东西**：能看见页面、能拿到完整结果、能知道"这步白做了"，
  这三样带来的提升，比换一个更贵的模型更确定。
- **失败要分类**：超时 ≠ 没通过 ≠ 没执行 ≠ 环境不可用。归错一类，后面整条修复回路都在修不存在的问题。
