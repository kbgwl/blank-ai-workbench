# B9 确定性 UI 冒烟（2026-11-22/23）

> 背景：B8 已把“预算保留 + 允许工具”修好，但最终提示词下完整 B7 里，模型仍有
> 一次 completely 不调用 browser_check 的轮次。B9 加一个**不依赖模型**的
> 兜底：验证节点自己启动工作区服务，做最小页面冒烟。

## 一、实现

- 新增 `services/api/src/blank_api/services/agent/ui_smoke.py`：
  - 只识别 `package.json` 的 `scripts.start` 且命令是 `node <file>`；
  - 用随机回环端口启动服务；
  - 用现有 `browser_probe.mjs` 打开首页，断言 `body` 存在、页面正文非空且
    不含 `undefined`，并 reload 一次；
  - 控制台/请求错误为 0 才通过；跑完立即杀服务。
- `graph.py` 的 UI 闸门：当**完全没有 browser_check 回执**时先尝试自动冒烟；
  通过则记 `ui.check_auto_passed`，页面失败/环境缺口仍走原来的失败路径。
- 不替代模型交互验收：模型有 browser_check 时，仍以模型的断言/动作为准；
  自动冒烟只在“模型完全没跑”时兜底。
- 测试：
  - UI 闸门自动冒烟兜底；
  - 原有 UI 闸门/预算保留/过渡/工具预算测试保持通过。

## 二、真机验证

### 2.1 直接调用自动冒烟（成功）

对 B7 工作区执行 `auto_ui_check`：

```json
{"status":"passed","url":"http://127.0.0.1:54974/","auto":true,"asserts":1,"steps":2,"console":0}
```

服务启动、页面打开、reload、正文断言和控制台检查均通过，服务已清理。

### 2.2 完整 B7 在 B9 下从头复跑（仍失败，但失败点不同）

- 任务 `dd95ba57-...`：**failed**，25 步 / 32 调用 / **1.709M token**；
- 这次模型**调用了 browser_check**（1 次），自动冒烟因此不触发；
- 失败原因是模型自己的 browser_check 步骤没有等待异步渲染：
  `#suggest-list .suggest` 和 `#chat-log .msg.ai` 断言在 AI 请求返回前执行，
  结果为 False；页面控制台 0 错误，接口测试 27 passed；
- 这是**检查脚本的时序问题**，不是“模型完全不验”，也不是页面打不开；
- 自动冒烟只覆盖“模型完全没跑”的路径，不覆盖“模型跑了但断言写错”。

## 三、结论

1. 自动冒烟在真实 B7 应用上能独立跑通；
2. 但完整 B7 这次失败于 browser_check 步骤缺少 wait，自动冒烟按设计不覆盖；
3. 下一步应补“click/type 后先 wait 再断言”的硬提示，或让 browser_check
   在动作后自动等待；不要再用完整大任务反复试错。

## 五、边界

- 自动冒烟只做“打开 + reload + 正文非空 + 控制台零错误”，不做复杂交互；
- 只支持 `node <file>` 的 start；npm/shell 启动、非 Node 项目返回 unavailable；
- 只有模型完全没跑 browser_check 时才触发；模型跑了但断言失败仍按模型结果；
- 没有跑完整后端 5000+；本轮 B9 相关 60 条通过。
