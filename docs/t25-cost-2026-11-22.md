# T25 文档任务成本收敛（2026-11-22，B6）

> 目标：B5 里 T25（README 用法示例）我们花了 **399K token / 16 轮 / 43 秒**，
> Claude Code 是 **138K / 14 轮 / 29 秒**。本轮只改成本，不改 UI、不扩任务集。
> 正确性以 T25 的隐藏验收为准，不能为了省 token 把交付做坏。

## 二、钱花在哪（用 evidence 说话）

首次复现的 evidence：

- 17 次模型调用，prompt 425K、completion 5.8K，缓存命中 93.8%；
- 首调 prompt **17,250 token**；工具说明 **22,467 字符**（34 个工具），
  系统提示 12,206 字符，任务本身只有 1,073 字符；
- 13 次 `execute_action`，18 个工具调用；其中：
  - `set "PYTHONPATH=src" && python -c ...` 返回 **9009（python 不在 PATH）**；
  - 模型接着 `where py` 再改用 `py -c`，白烧两轮；
  - 之后写 `.blank/scratchpad/verify_readme_examples.py`、读回、执行，
    又读 README 两次、查 `git status`、跑 `doctest`；这些都不是交付必需。

真正的大头不是 completion（只 5.8K），而是**每轮重发的工具说明书 + 历史**。

## 三、改了什么

### 3.1 链式命令里的裸 `python`

`services/api/src/blank_api/services/tools/shell.py`

- `normalize_python_command` 从“只看命令第一个词”改为**按 `&&` / `||` / `|` /
  `;` 分段替换**，引号内的分隔符不切；
- 工作区没有 venv 时，`run_shell` 回退到 `sys.executable`（与 `run_tests`
  的 `python_test_command` 同源），解决 Windows 上 `python` 不在 PATH 的 9009；
- 用户显式 `set "PATH=..."` / `export PATH=...` 时不替换，保留用户指定解释器；
- Docker 档不回退宿主解释器，避免容器里拿到不存在的宿主路径；
- `2>&1` 里的单个 `&` 不当分隔符。

### 3.2 文档-only 任务收窄工具表

- `directives.py`：`documentation_only(goal, acceptance)`。
  只有“目标是 README/文档”且“用户写了不改源码/只改文档，或验收写了未修改 src”
  才成立；只出现 README 不算。
- `registry.py`：`DOCS_ONLY_EXCLUDED`（任务台账、子代理、技能发现、浏览器、
  notebook/REPL、计划模式、report_findings 等 18 个入口）。
- `runtime.py`：命中文档-only 时从本任务注册表排除这些工具，并落
  `tools.excluded` 事件；`tool_search`、读写文件、`run_shell`、`run_tests` 等
  核心面保留。
- 工具说明从 **22,467 字符降到 11,192 字符**，工具数 34→16；首调 prompt
  从 17,250 降到约 12K token。

### 3.3 文档-only 执行纪律

系统提示追加一条（只对本任务生效，不覆盖安全/审批边界）：
“只改指定文档、不要改源码；只读目标文档与直接引用的源码，不扫全仓；不写
临时校验脚本；除非明确要求不查 git/浏览器/任务台账；最后跑一次 run_tests。”

这条把 T25 的 18 个工具调用压到 **8 个**（读 3 个文件 + 一次 run_shell
核对输出 + edit_file + run_tests）。

## 五、边界

- 文档-only 是**显式边界**识别，不是“所有提到 README 的任务都收窄”。用户没写
  “不改源码/只改文档”、验收也没写“未修改 src”时，仍走全量工具表（省不到，
  但不会误伤需要改源码的任务）。
- 如果文档任务实际需要浏览器/git，模型会看不到这些工具；这类任务不应被标成
  “只改文档、不改源码”，或需要用户在指令里明确要求。
- 收窄是**任务级排除**，`tool_search` 也拉不回被排除项；这是有意的，避免
  “先收窄、模型一搜又全回来”。
- 本轮验证 T25、T01 回归与四任务复跑；后端全量
  **5033 passed / 28 skipped**（18:44）通过。解释器改动有 161 条相关回归。
- 文档-only 的工具收窄仍是产品决策，不是通用结论；其他场景是否照此收窄
  需要单独评估。
- 这是单模型（DeepSeek）结果，spark-x2.6 上的成本曲线未复测。
