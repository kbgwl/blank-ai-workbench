# 空白格 bot

首页是一个对话界面，不再是"智能体操作台"。

> 为什么叫 bot、内核却是 agent：见 [BOT-VS-AGENT.md](./BOT-VS-AGENT.md)。
> 一句话——bot 说的是表面，agent 说的是谁决定下一步；两者不在同一个轴上。

## 形态

```
┌─────────────┬──────────────────────────────┬───────────────┐
│ 会话列表     │ 对话                          │ 最新一轮       │
│ 今天/昨天/…  │  · 你说的话（右侧气泡）        │ · 工具调用数   │
│ 搜索         │  · 它做的事（可折叠的步骤）    │ · 改动文件     │
│ 新对话       │  · 它的回答（markdown）        │ · 耗时/token  │
│             │  · 审批与提问（内联卡片）      │ · 文件 diff    │
│             ├──────────────────────────────┤               │
│ 设置         │ 输入框（@ 引用 / 模型 / 发送） │               │
└─────────────┴──────────────────────────────┴───────────────┘
```

一轮对话在后端仍然是一个普通任务：有自己的目标、事件、工具调用和总结。
bot 没有新增执行入口——运行、审批、中断、恢复、证据全部复用原有路径。
"多轮"由 `threads` 表串起来（见 `REA-WAVE2-PROTOCOL.md` 7.9）。

## 必须守住的四条判断

**1. 事件要折叠成人话。**
后端事件是审计材料：一次工具调用拆成 `tool.requested` / `tool.completed`，
中间夹着 `context.measured`、`guardian.reviewed`、`node.started`。
直接铺开是几十行机器话，用户看不出"它到底改了什么"。
`bot/turns.ts` 只保留计划、工具、文件变更、提问、审批五类动作，其余丢掉。

配对靠**顺序**而不是时间：后端 `graph.py` 的收尾段明确"按模型给出的顺序写事件"，
所以同名调用按下标一一对应。按结束先后配会把并发读取的输出张冠李戴。
配不上的 `completed` 仍然保留——宁可多一条"执行完了"，也不能让真实发生过的操作消失。

**2. 流式输出不能吞掉正文。**
未闭合的 ` ``` ` 按代码块渲染，而不是等闭合。否则模型正在写代码时，
后面的内容会凭空消失一段时间。同理两处：
- 实时文字只在**还跑着**的那一轮显示，任务结束后换用事件里的完整回复，
  两处同时显示会出现一段重复的话。
- 历史轮次只给最近 6 轮拉事件；更早的轮次显示目标与结论，不展开过程。
  想看可以点开单独拉——但默认不该为了翻十轮前的对话发十几个请求。

**3. 不把模型输出当 DOM。**
markdown 解析器不实现 HTML。模型输出里的 `<div onclick=…>` 必须原样显示成文字。
这是一个能改文件、能跑命令的程序，把它的输出当页面结构用，等于把方向盘交出去。

**4. 正文只写判断，过程事实交给依据条。**

回复长的根因不是模型话多，是**同一件事被写了两遍**：正文说「改了 A、跑了 B、测试通过」，
而这两条事实步骤区本来就有。让它「少写」没用——压句子压出来的还是复述，只是变短了的复述。

所以分工是硬的：

| | 归谁 | 内容 |
|---|---|---|
| 事实 | 步骤区（`turnEvidence()`） | 看了几次 / 改了哪些文件 / 跑了什么命令 / 失败几次 / 花了多久 |
| 判断 | 正文 | 为什么这么改、哪条路被否了、还剩什么风险、需要你做什么 |

前者从事件流算得出来，后者算不出来——**正文只写算不出来的**，长度自然就短了，而且短下来不丢信息。

三个配套约束：

- **依据条可点开**：一行数字，点开逐条落到具体的行；展开区还能切「全部 / 改动 / 失败」。
- **文件名做锚点**：正文里写 `composer.tsx` 或 `bot/composer.tsx`，能认出是本轮改过的哪个文件，
  渲染成可点，点了展开并切到「改动」。**同名文件有歧义时不做成可点**——点错地方比点不动糟得多。
- **空段省略**：交付文本原先把空段填「无」，于是「未完成 / - 无 / 下一步 / - 无」白占四行，
  读者还得先确认是空还是漏写。"都做完了"结论段自己会说，依据条上「0 次失败」也在说。
  只有正文、没有小标题时也原样返回，不再套成三段。

工具侧的纪律写进 `SYSTEM_PROMPT`，每条都能从事件流判定，不是口号：
每次调用要有能说清的目的、写之前先读、失败不原样重试、同一份信息不取两次。
「只写不读」在依据条上表现为 `看了 0 · 改了 2 个文件`——**它是可观测的**，这比要求模型
"先读再改"有用。

两个数字必须同源：对话里的依据条和右侧面板都调 `turnEvidence()`。左边说改了 3 个文件、
右边说 4 个，用户就没有理由相信任何一个。

## 交互上的几个选择

| 动作 | 行为 | 为什么不那样 |
|---|---|---|
| 按回车（空闲） | 新建一轮并**立刻启动** | 不先建草稿等用户点运行：在 bot 里按回车就是"去做" |
| 按回车（运行中） | 插话（steer） | 同一轮里改方向，比等它跑完再纠正省一次重复执行；提示写"已排队"，因为后端语义是从下一次模型调用生效，不撤回已执行的动作 |
| 点某条会话 | 载入全部轮次，最后轮接管 SSE | — |
| 归档 | `status=archived`，轮次全留 | 删会话会把任务的 `thread_id` 置空，那些轮次再也串不回去 |
| 分叉 | 记 `forked_from`，不复制任务 | 复制任务等于复制它的全部事件与审计记录 |
| 深链 | `?thread=<id>` | 刷新能回到原处，也能把一条对话直接发给别人 |

## 打包与装机

```bash
# 1. 静态导出（桌面壳没有服务器，前端直连本机后端）
cd web
BLANK_DESKTOP_BUILD=1 NEXT_PUBLIC_API_BASE=http://127.0.0.1:8000 npx next build

# 2. 打包
cd ../desktop
NODE_OPTIONS= npx electron-builder --win nsis portable

# 3. 自检（14 项，其中「首页是 bot 对话页」专门防「能打开但还是旧操作台」）
node verify-package.cjs

# 4. 本机覆盖安装
node install-local.cjs
```

安装目标目录写在 `desktop/install-target.local.json`（`{"dir": "D:\\a\\b"}`，不入库）。
**不要把路径从 shell 传进来**：NSIS 的 `/D=` 只认反斜杠，而 `/D=D:/a/b` 会被它把斜杠
整个吃掉，装到 `D:ab` 去；反斜杠从 git-bash 传进来又同样会被吃掉。两条路都试过，
都真的装错地方（还会在磁盘根目录留下 `Softwareskbgblank-...` 这种畸形目录）。
文件里的转义是给 JSON 解析器的，node 读出来就是真反斜杠，不经过任何 shell。

装机前先备份用户库（`%APPDATA%/blank-ai-workbench-desktop/blank.db`）。旧版本残留的
卸载注册项指向哪，重装就往哪走——装错位置后要先把那条 `Uninstall` 键删掉再装，
否则安装器会去跑一个路径已经不存在的卸载器然后卡住。

## 让它改自己

工作区指向本仓库，所以它可以读自己的源码、改、跑测试。但**改完不会自动生效**：
装好的客户端跑的是 `resources/` 里的副本（后端 `resources/backend/api/src/blank_api`、
前端 `resources/web`），不是工作区里的源码。少了同步这一步，球是进了，计分牌没动。
看起来最像"没生效"或者"它改错了"，其实只是还没搬过去。

```bash
node desktop/self-deploy.cjs           # 后端 + 前端 + 壳入口
node desktop/self-deploy.cjs --api     # 只后端（秒级）
node desktop/self-deploy.cjs --web     # 只前端（会重建静态站，约 20s）
node desktop/self-deploy.cjs --shell   # 只壳入口（main.cjs / preload.cjs / gpu-guard.cjs）
node desktop/self-deploy.cjs --dry-run # 只看会做什么
```

同步完要**完全退出客户端**再打开：后端是客户端启动时拉起的子进程，不重启还在跑旧代码。
只改前端时可以在窗口里按 Ctrl+R 先看。

脚本的两个细节不是可有可无的：
- **先删目标再拷**。直接覆盖会把源码里已删除的模块留在包内，于是"删掉的代码还在跑"。
- **排除 `__pycache__` / `*.pyc`**。带进去的旧字节码会让 import 忽略改过的 `.py`，
  表现为"改了但行为没变"，而且 traceback 里的行号对不上。

壳入口（主进程 `main.cjs` / `preload.cjs` / `gpu-guard.cjs`）在 `resources/app.asar` 里。
`--shell`（以及默认的全量同步）会解包、换掉这三个文件、再打回去——效果等同重新打包，
但不用跑一遍 electron-builder。两个前提：**客户端必须完全退出**（app.asar 被占用时会直接
报 EPERM 并给出这句话），以及旧包会备份成 `app.asar.bak`。文件没变时它什么也不做。

## 取消之后卡死：一句 409 把整个输入框废掉（0.8.12）

现象很具体：**点过停止（或这一轮在别处被取消）之后，界面仍然显示"进行中"，右下角还是那个
方形停止钮；此后输入的任何一句话都会立刻变成底部那条红字 ——「任务已结束，无法插话
（当前状态：cancelled）」。** 刷新页面能好，但没人知道要刷新，看到的就是"这个产品不能用了"。

这不是一处 bug，是四层叠出来的死锁：

| 层 | 当时的做法 | 后果 |
| --- | --- | --- |
| 接口 | `POST /tasks/{id}/cancel` 只改 `status` + 写 `task.cancel_requested`，真正的 `task.cancelled` 留给运行时收尾 | 运行时不一定走得到收尾（模型调用挂在半路、任务已被别处标记结束、进程已退出），时间线上**永远没有终态** |
| 判据 | 前端 `isTurnRunning` 只认 `task.completed` / `task.failed` / `task.cancelled` | `cancel_requested` 被当成"还在跑" |
| 同步 | 只有 `!running` 时才去 `fetchTask` | 一旦判成"在跑"，就再也不问真实状态 → 永远在跑 |
| 交互 | 跑着时按回车走"插话"，失败只把错误显示出来 | 409 变成一句红字，输入框还是发不出去 |

四条里任何一条单独存在都不致命，凑在一起就是"停不掉、也发不出去"。

**修法（四条一起，缺一条都还会卡）：**

- 取消端点**当场落一条终态事件**（先问 `has_terminal()`，已有就不重复写——同一轮结束两次
  会让台账需要解释）。
- `isTurnRunning` 把 `task.cancel_requested` 也算结束：它本来就是"已经在取消"的确证，
  这时候用户想说的是下一句，不是往一个停下的轮次里塞话。
- 跑着的时候**每 4 秒核对一次任务状态**。事件流只带时间线、不带状态，而状态可能被
  别处改（取消、队列标失败、后端起停）。这一条是兜底：不管以后从哪儿冒出新的状态变化，
  界面最多落后 4 秒。
- 插话收到 `task_not_steerable` 时**自动改走新一轮**，并把提示写成"上一轮已经结束，
  这句话作为新的一轮发出"。把"状态没同步"放大成"这个功能废了"，不值得。

顺带改掉一处同类体验：**没有工作目录时不再把请求发出去**。以前是任务先建出来、`/start`
再回 409「该项目尚未绑定工作区目录」——界面上多一条永远停在 queued 的轮次，用户看到的是
"发不出去也说不清为什么"。现在本地就拦住，顺手把系统目录框弹出来，一步选完即可开始；
输入框的占位文案也会直接写"还没有工作目录"。

**闸门**（都能失败，不是摆设）：

- `tests/test_post_commit_refresh_v30.py::test_cancel_writes_a_terminal_event_right_away`
  量的是时间线本身：取消后必须有且只有一条 `task.cancelled`。把那段写回去掉，它会红成
  `['task.created', 'task.cancel_requested']`——正是用户看到的死锁成因。
- `web/src/components/bot/turns.test.ts` 里那条把 `cancel_requested` 钉成"已结束"，
  同时钉住"paused 不算结束"（驳回高风险操作后还能接着说一句）。

## 不问就编：一句「帮我做个公司官网」的代价（0.8.13）

用户的原话：**「碰到不知道的问题也不提问，就自己瞎干」**。界面上的读数是：14 次工具调用、
4 次失败，产出 4 个文件，结论里再来一句「请替换占位名称、电话、邮箱和案例数据」。

它不是做错了，是**没问**。公司叫什么、给谁看、要哪些栏目、联系方式是什么，这些只有用户
知道；模型默认全部自己编，编完还留下"请你替换"——用户拿到的是「看起来做完了」，实际每个
关键字段都要重填一遍，比一开始答三句话贵得多。

先排除掉两种"其实通道坏了"的可能：

| 疑点 | 实测 |
| --- | --- |
| 工具没注册 | `request_user_input` 在 `CORE_TOOLS` 与 `LEAN_TOOLS` 里，lean 档也保留 |
| 端到端不通 | 后端 `POST /tasks/{id}/questions` 收答案，`_question_gate` 用中断通道挂卡，`_dispatch` 在有答案时 `ok=True` 并把 `【用户回答】` 回填进上下文 |
| 前端不显示 | `bot-app.tsx` 有 `PendingQuestion`、`questions={turn.questions}` 与 `answerQuestion` 回调 |

通道是通的，一次都没用上。原因是 `SYSTEM_PROMPT` 里**没有一条规则要求它问**：16 条规则
教它怎么干活、怎么少说话，没有一条说「信息不够时先问」。工具描述还反向推了一把——
`「不要用它确认显而易见的事；能自己查证的就先查证」`，读起来像「尽量别用」。

### 三层修法

1. **提示词**：在 `SYSTEM_PROMPT` 最前面加一段「先问再干」，排在「做事规则」之前。
   位置不是随手放的：规则后面的会被长上下文冲淡，最先失效的就是它们。五条边界——
   什么必须问（只有用户知道的信息）、什么不许做（拿占位值顶替）、什么不要问（技术方案、
   能查到的）、问过的别再问、卡住两次要停下来问而不是绕过去。
2. **工具描述**：补上正向的那一半。原来只有「别乱问」，现在是「该问时必须问 + 不该问的
   别问」，两侧都有。
3. **确定性审计**（`services/agent/placeholders.py`）：提示词是概率性的，它一定会漏。
   所以再加一层不看模型的：扫本轮**写类工具的参数**，找出几乎不可能是有意为之的占位值
   （`example.com`、`138-0000-0000`、`lorem ipsum`、「示例公司」「待填写」），
   - 进了 `review.completed` 的 `placeholder_hits`（依据条里看得见）；
   - 交付正文末尾补一句 **模型改不掉** 的话：「这一轮有内容用的是占位值（…）——它们是我
     编的，换成你的真实信息才算完成」。

   审计刻意收窄：`TODO`、`placeholder`、`xxx` 这些在正常代码里到处都是，算进来就会把
   「写了个表单」判成「用了占位」，那这层审计就没人信了。只在**本任务没问过用户**时报——
   问过之后那些值就是用户给的，再说"这是占位"是冤枉它。

### 闸门

`tests/test_placeholder_audit_v146.py`（8 例，全部能失败）：

- `先问再干` 必须在 `SYSTEM_PROMPT` 里，且**位置在「做事规则」之前**（用 `index` 比）；
- 占位能识别，且 `TODO` / `placeholder=` / `xxx` 不误报；
- 只审写类工具：`search_code` 的参数里搜「example.com」不算占位；
- 同一占位值出现二十次算一个问题，不是二十个；
- **问过用户之后那句话必须消失**（变异验证：拿掉追加那行，这条立刻红）。

### 一句实话

这一层管不了「不写占位、直接编一个像样的名字」——那种情况审计抓不到，只有模型自己提问
才能解决。所以真正的开关是提示词那五条；审计的作用是**不让它假装完成**，而不是拦住它。
如果之后仍然观察到"编完就交"，下一步该动的是流程（从零创建类任务先出方案再执行），
不是继续往提示词里加句子。
