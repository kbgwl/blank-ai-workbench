# 最终目标路线图：质量追平 Claude/Codex · 速度快 · token 极少

> 来源：2026-11-24 质量验收 + 内核实测（代码级，非文档转述）
> 状态：目标路线图
> 关联：kbgai 空白格 AI 操作台

## 一、最终目标

**质量高过国内所有产品（参照系为 Claude Code / Codex）∧ 速度快 ∧ token 使用尽可能少。**

三个目标不是并列的：**token 是最大短板，同时拖累质量与速度**。先治 token，质量与速度自然受益。

## 二、目标拆解与可度量判据

| 维度 | 当前实测基线 | 达成判据 |
|---|---|---|
| 质量 | 对标 Claude Code 4/4 通过、96.5 vs 97.5 | 隐藏验收通过率 100%、零改动伪成功拦截 100%、验收覆盖 1.0、独立事实核验全过 |
| 速度 | 平均 25s/任务（与 Claude 持平） | 同批任务耗时 ≤ 国内产品、超时率 0 |
| token | 平均 225K/任务，Claude 的 1.76 倍（T25 2.89 倍） | 同批任务 token ≤ 国内产品、历史膨胀率显著下降 |

## 三、质量参照系（关键）

业界主流认知：

- **Claude（Anthropic）**：编码质量最高。
- **Codex（OpenAI）**：紧随其后。
- **国内产品**（DeepSeek / 通义 / Kimi / 智谱 / 讯飞）：模型能力接近，harness（执行框架）弱一档。

**关键洞察（kbgai 实测）**：质量 = 模型 × harness。kbgai 对标中，Claude Code 也用 DeepSeek 模型
（`deepseek-flash[1m]`），同一模型下 kbgai 96.5 vs Claude Code 97.5——**差距在 harness，不在模型**。
模型可换，harness 可学，因此「追平 Claude / Codex」不是空想。

**参照系修正**：「高过国内产品」只是底线，真正对标的是 Claude Code / Codex。

## 四、现状差距（实测确认）

**token 浪费点（实测）：**

- 写类工具返回全文 diff（`editing.py`），模型写过的文件在历史里反复重发。
- 上下文单调增长（历史回放，模型重读自己刚写的代码）。
- 调用次数多（T09 类文档任务 19 次调用，每轮重发历史）。

**质量待补（实测）：**

- `done_when` 判据已实现，但**不设 blocking**：判据不过只记 finding、不判死。
- 审查无确定性输入边界。
- 钩子失败无法 fail-closed（安全类钩子崩了会放行）。

**速度：**

- 已与 Claude 持平；token 下降后每轮更快，自然受益。

## 五、达成路径（按杠杆排序）

### 第一优先级：直接降 token

1. **写类工具只回执**：`editing.py` 去掉全文 diff，改为「已写入 `<path>`（N 行变更）」。
2. **当前文件状态快照取代历史回放**：治上下文单调增长。
3. **压调用次数**：定位 T09 类任务为何需要 19 次调用。

### 第二优先级：质量防「假成功」

4. **`done_when` 判据设为 blocking**：从「摆事实」升级为「一票否决」。
5. **审查前确定性范围**：补 baseSha / 四组路径硬事实（对标 DSH change-scope）。
6. **钩子 fail-closed**：给 `HookSpec` 加 `on_failure: block`。

### 第三优先级：速度

7. **推测性工具执行**：流式输出时提前跑只读工具（延迟优化）。
8. **删系统提示对照实验**：删一半 → 同批任务对照成功率与步数。

## 六、验收与度量（否则无法证明「高过」）

- **独立可复现评测**：用 `evals/` 扩充任务集（编程 / 修 bug / 文档 / 数据 + 多文件真实项目），
  同一套隐藏验收跑国内各产品，**不以交付文本自述为准**。
- **每项优化出对照数字**：改前改后同批任务的 token / 耗时 / 通过率，用 `evals/compare.mjs` 出数。
- **补跑 Codex**：上次对标 Codex 未跑成（账号模型不可用），恢复可用模型后补跑同一组任务，
  否则对外只能说「Codex 未对比」。
