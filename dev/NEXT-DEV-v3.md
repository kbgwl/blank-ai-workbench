## 三、任务拆解（按序）

### 任务 1：压调用次数第二轮（核心）

**1a. 工具说明书瘦身**
- 现状：34 个工具说明书每轮约 22,467 字符，是每轮固定成本大头。
- 做法：按使用频率与场景裁剪说明书，合并重复描述，低风险项优先。
- 涉及：`services/api/src/blank_api/services/tools/registry.py`、工具说明书装配处。
- 验证：T09/T01 每轮固定成本下降，调用数与 token 同步下降。

**1b. 执行层合并（并发白名单）**
- 现状：非 `PARALLEL_SAFE_TOOLS` 的调用按顺序跑，同批只省模型往返、不省磁盘时间。
- 做法：不同文件的独立写/改加入并发执行白名单，同一批内真正并行落盘。
- 涉及：`services/api/src/blank_api/services/agent/` 执行层（graph.py / dispatch 相关）。
- 验证：同批多文件写/改耗时下降；正确性不降（编辑顺序、备份不受影响）。

**1c. 提示词强化**
- 现状：编辑前仍有重读（read_file 约 7 次）。
- 做法：进一步明确「写前不重读、用写入原文做锚点、同批多文件写/改」，降低重读。
- 涉及：`services/api/src/blank_api/services/agent/graph.py`（SYSTEM_PROMPT）。
- 验证：T09 read_file 次数下降，调用数 ≤12。

### 任务 2：修 P1：场景分流 + 授权边界 + 统计口径（不一刀切禁扫描）

> 重要：用户明确要求「修复电脑」的整机检查/清理，必须允许扫描系统目录，
> 不能一刀切禁止全盘扫描。正确做法是**按场景分流 + 授权 + 边界控制**，
> 并修正统计口径。

**设计理由（对应用户明确诉求）**：修复电脑必须能扫全盘，否则解决不了问题，
因此本任务**不设"禁止全盘扫描"这条规则**，只约束"普通任务的默认行为"。
被保留的是能力（明确授权后可扫系统目录），被约束的是默认（普通任务不主动扫系统目录），
既满足修电脑场景，又消除 T09 那次因误扫系统目录导致的误扣分。

- **场景分流**：
  - 普通任务（编程/文档/数据处理）默认只在工作区内操作，不主动扫描系统目录，
    避免误操作与评测扣分。
  - 用户明确要求「修复电脑 / 检查清理 C 盘」时，进入整机检查/清理通道，
    复用 E12 已实现的跨盘盘点能力（先只读盘点、列清单、等明确同意、逐项执行）。
- **授权与边界控制**：
  - 扫描系统目录需用户明确授权；盘点固定位置（%TEMP%、C:\Windows\Temp、
    回收站、更新缓存等），单目录设时间上限（60 秒），不在系统盘根目录写扫描文件。
  - 系统/用户/缓存分类处理，不自动删系统关键文件；清理先列清单、用户确认后逐项执行。
- **统计口径**：`changed` 只统计工作区内（或用户明确授权范围内）的模型改动；
  工作区外系统文件的 mtime 变化（系统自身行为）不计入，避免误判「模型改动」扣分。
- 涉及：工作区边界提示、整机检查/清理通道（E12）、`_snapshot_changed_paths` / 变更统计处。
- 验证：
  - T09（普通文档任务）不再全盘扫描，`minimal` 恢复、分数回升。
  - **「修复电脑 / 清理 C 盘」类请求真机实测**：能正常走授权盘点通道，
    扫描系统目录成功、清单正确、用户同意后逐项清理正确执行，
    且其系统文件改动不计入 `changed`、不触发误扣分。

## 五、风险与注意

- 并发写/改必须确认文件独立、无依赖，避免编辑顺序错乱与备份冲突。
- 提示词强化不能牺牲编辑正确性：锚点容错已有（引号/空白/CRLF），失败会明确报错。
- 系统文件排除不能掩盖真实越界：记录越界尝试，只是不计入「模型改动」评分。
- 工具说明书瘦身不能删模型必需的参数说明，裁剪后回归工具调用正确性。
- 真机对照需后端运行（SQLite 模式即可，无需 Docker）。
