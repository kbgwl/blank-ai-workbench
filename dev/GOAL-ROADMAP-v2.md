## 一、最终目标（升级）

**质量优于 WorkBuddy、Qoder、Trae 与国内主流 harness；速度比它们更快；token 使用尽可能少。**

- 质量天花板参照仍为 Claude Code / Codex（前者当前 97.5 分，kbgai 同模型下 96.5，差距 1 分）。
- 三个目标不是并列：**token 是最大短板，同时拖累质量与速度**，先治 token，质量速度自然受益。

## 四、需要补足的（现状差距，实测确认）

**token 浪费点（实测）：**

- 写类工具返回全文 diff（`editing.py`），模型写过的文件在历史里反复重发。
- 上下文单调增长（历史回放，模型重读自己刚写的代码）。
- 调用次数多（T09 类文档任务 19 次调用，每轮重发历史）。

**质量待补（实测）：**

- `done_when` 判据已实现，但**不设 blocking**：判据不过只记 finding、不判死。
- 审查无确定性输入边界（缺 baseSha / 四组路径硬事实）。
- 钩子失败无法 fail-closed（安全类钩子崩了会放行，无 `on_failure` 字段）。

**速度待补（实测）：**

- 推测性工具执行未做（流式输出时无法提前跑只读工具，存在延迟损耗）。

## 五、需要升级的（达到新目标必须做）

**质量升级（产出更好）：**

1. **`done_when` 判据设为 blocking**：从「摆事实」升级为「一票否决」，让「判据没过」真正判死。
2. **审查前确定性范围**：补 DSH `change-scope` 式的 baseSha / 四组路径硬事实，审查才有稳定输入边界。
3. **钩子 fail-closed**：给 `HookSpec` 加 `on_failure: block`，安全类钩子失败必须阻断。
4. **独立评测体系升级**：用 `evals/` 扩充任务集（编程 / 修 bug / 文档 / 数据 + 多文件真实项目），
   同一套隐藏验收**同时跑 WorkBuddy、Qoder、Trae 与国内主流 harness**，
   产出质量以评测数字为准，不以交付文本自述为准。
5. **零改动伪成功拦截保持 100%**：`verify_facts` 已有机制，纳入常规评测回归。

**速度升级（更快）：**

6. **推测性工具执行**：模型流式输出时提前跑只读工具（`read_file` / `glob` / `search_code`），降延迟。
7. **压调用次数**：定位 T09 类任务为何 19 次调用，减少每轮往返。
8. **token 下降后每轮更快**：上下文变小，单轮耗时自然下降。

**token 升级（更少）：**

9. **写类工具只回执**：`editing.py` 去掉全文 diff，改为「已写入 `<path>`（N 行变更）」。
10. **当前文件状态快照取代历史回放**：治上下文单调增长，模型不再重读自己刚写的代码。
11. **删系统提示对照实验**：删一半 → 同批任务对照成功率与步数，能删则永久删。

## 六、达成路径（按杠杆排序）

7. 独立评测体系升级（纳入 WorkBuddy / Qoder / Trae 对标）。

### 第三优先级：速度升级

8. 推测性工具执行。
9. 删系统提示对照实验。
